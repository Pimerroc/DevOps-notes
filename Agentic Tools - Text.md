Архитектура Agentic Loop в проекте состоит из нескольких взаимодействующих компонентов.

Первый компонент — API-слой. Он принимает запрос пользователя, загружает историю диалога и состояние программы, после чего запускает обработку.

Второй — Agentic Loop. Это основной цикл взаимодействия с языковой моделью. Модель получает контекст и либо возвращает текстовый ответ, либо запрашивает выполнение инструмента. Если нужен инструмент, цикл передаёт запрос на исполнение, получает результат и возвращает его модели. Процесс повторяется до завершения задачи или достижения лимита итераций.

Третий компонент — Tool Registry. Он определяет доступные инструменты, проверяет аргументы и запускает соответствующие функции. Например, поиск источников или сохранение блока образовательной программы.

Четвёртый компонент — LLM Provider. Он обеспечивает взаимодействие с языковой моделью и позволяет использовать разных провайдеров через общий интерфейс.

Пятый и шестой компоненты — состояние программы и Persistence. Состояние отражает прогресс выполнения этапов, а PostgreSQL и Redis используются для хранения данных. Механизм checkpoint позволяет сохранять промежуточные изменения после выполнения инструментов.

Важно различать Agentic Loop и pipeline: первый управляет взаимодействием модели с инструментами, а второй — последовательностью этапов создания образовательной программы.
