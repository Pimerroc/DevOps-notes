# Livecoding Coach

## Когда использовать

- Пользователь просит livecoding, парное программирование, практику в nvim или анализ того, как он пишет код/конфиги.
- Команда `/live`.
- Нужно собрать объективные метрики: скорость, паузы, откаты, сохранения, команды, диагностика LSP.

## Жёсткое правило невмешательства

После запуска сессии:

- не подсказывай;
- не задавай вопросы;
- не комментируй код;
- не проверяй лог и не полли;
- не отправляй сообщения, пока пользователь не напишет `готово`, `стоп` или явно не попросит помощь.

Если пользователь задал вопрос — ответь только на него и снова вернись в режим молчания.

## Workflow

### 1. Preflight

Проверь наличие:

```bash
command -v python3
command -v nvim
command -v kitty
```

Если `kitty` нет — предложи ручной запуск через `launch.sh`, который создаст setup-скрипт.

### 2. Setup

Из корня vault:

```bash
python3 .zcode/skills/livecoding/scripts/setup.py \
  --topic "<тема>" \
  --task "<задача>"
```

Опционально:

```bash
--file main.py          # файл в workspace, по умолчанию main.py
--no-launch             # только создать сессию и launch.sh
```

Скрипт создаёт:

- `DevOpsNotes/Practice/livecoding/<session-id>/workspace/` — рабочая директория;
- `DevOpsNotes/Practice/livecoding/<session-id>/session.json` — метаданные;
- `DevOpsNotes/Practice/livecoding/<session-id>/launch.sh` — ручной запуск;
- `~/.local/share/opencode/livecoding/<session-id>/session.jsonl` — сырой лог;
- окно `kitty` с `nvim` и логгером;
- окно `kitty` с live-метриками.

После setup отправь ровно одно сообщение:

> Сессия запущена. Работай. Когда закончишь — напиши «готово».

И остановись. Не вызывай инструменты, пока пользователь не вернётся.

### 3. Во время сессии

Ничего не делай. Live-метрики показывает отдельное окно `watch.py`. Оно не пишет в workspace и не мешает.

### 4. Анализ после «готово»

```bash
python3 .zcode/skills/livecoding/scripts/analyze.py \
  --session DevOpsNotes/Practice/livecoding/<session-id>/session.json
```

Скрипт создаёт:

- `metrics.json` — машинные метрики;
- `summary.md` — человекочитаемый отчёт.

Прочитай `summary.md` и файлы в workspace. Дай обратную связь в порядке:

1. объективные метрики;
2. наблюдаемые поведенческие паттерны;
3. 3 вопроса на рефлексию;
4. рекомендации на следующую сессию.

Не утверждай, что «прочитал мысли». Метрики показывают поведение, а не намерения. Причины пауз и откатов выясняй вопросами.

### 5. Заметка

Создай или обнови:

- `DevOpsNotes/Practice/livecoding/<session-id>/README.md` — отчёт по сессии;
- `DevOpsNotes/DevOps/Learning Log.md`;
- `DevOpsNotes/DevOps/Skills Matrix.md`;
- `DevOpsNotes/DevOps/Review Queue.md`.

В заметке укажи:

- тему и задачу;
- метрики;
- что сломалось;
- что переделал;
- выводы;
- `review_at`.

## Что измеряется

- длительность и активное время;
- символы в минуту, WPM (1 слово = 5 символов);
- нажатия клавиш и нажатия в минуту;
- доля удалений;
- паузы > 30/60/120 секунд;
- крупные откаты (delta ≤ −50 символов);
- сохранения и команды `:` (только имя команды, без аргументов);
- переключения файлов и режимов;
- диагностика LSP: ошибки/предупреждения;
- потеря/получение фокуса.

## Ограничения

- Агент не наблюдает терминал непрерывно: live-анализ делает локальный `watch.py`, а агент разбирает записанные метрики после сессии.
- Метрики не доказывают «неправильное мышление». Это поведенческие сигналы; причины выясняются ретроспективой и ревью кода.
- Сырые логи лежат вне vault, в `~/.local/share/opencode/livecoding/`, и не коммитятся.
- Логгер пишет только метаданные: не пишет содержимое буфера и полные команды. Секреты всё равно не вводи в livecoding-сессии.
- Если `kitty` или `nvim` недоступны, используй `launch.sh` и ручной запуск.

## Проверено

- nvim 0.12.6 + kitty: события `start`, `buf_enter`, `edit`, `save`, `stop` пишутся.
- Headless-тест: таймер фиксирует изменения буфера, даже если `TextChanged` не сработал.
- `setup.py --no-launch`, `analyze.py`, `watch.py` прошли smoke-тест; `metrics.json` и `summary.md` создаются.
- Живой ввод с клавиатуры проверяется в первой реальной сессии; `vim.on_key` считает нажатия.
