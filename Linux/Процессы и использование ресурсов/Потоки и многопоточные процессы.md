## Что такое поток

Обычно процесс можно представить как отдельную выполняемую программу.

Однако процесс может содержать несколько потоков выполнения.

Упрощённо:

```text
однопоточный процесс

process
   │
   └── thread
````

или:

```
многопоточный процесс

process
   ├── thread 1
   ├── thread 2
   ├── thread 3
   └── ...
```

---

## PID и TID

Для просмотра потоков можно использовать:

```
ps m
```

В книге приводится:

```
ps m -o pid,tid,command
```

Пример структуры:

```
PID    TID    COMMAND
3587   3587   bash
3592   3592   bash
12534  12534  /usr/lib/xorg/Xorg ...
       13227
       14443
       14448
```

---

## Основной поток

У однопоточного процесса:

```
PID = TID
```

То есть основной поток имеет идентификатор, совпадающий с PID процесса.

У многопоточного процесса основной поток также имеет TID, совпадающий с PID.

Например:

```
PID процесса: 12534
TID основного потока: 12534
```

Другие потоки получают собственные TID.

---

## Потоки и мониторинг ресурсов

Потоки могут усложнять мониторинг.

Причина:

несколько потоков одного процесса могут одновременно использовать ресурсы.

Например:

```
process
├── thread A → CPU
├── thread B → CPU
└── thread C → memory / I/O
```

Поэтому отображение процесса как единственного объекта не всегда показывает полную картину его внутренней активности.

---

## top и потоки

По умолчанию `top` не отображает отдельные потоки.

Для их включения используется клавиша:

```
H
```

После этого можно наблюдать отдельные потоки.

Однако книга отмечает, что обычно пользователь не взаимодействует с отдельными потоками так же, как с обычными процессами.

Для воздействия на отдельный поток необходимо хорошо понимать:

- устройство многопоточной программы;
- её внутреннюю архитектуру.

И даже в этом случае вмешательство в отдельный поток обычно не является хорошей идеей.

---

## Главная идея

Поток — это не отдельный независимый процесс.

Несколько потоков относятся к одному процессу и могут совместно использовать ресурсы процесса.

Поэтому:

```
один процесс
≠
всегда одна линия выполнения
```

При анализе производительности необходимо учитывать, что активность одного процесса может быть результатом работы нескольких потоков одновременно.
