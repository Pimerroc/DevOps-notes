## Группы

Группа — механизм организации совместного доступа к файлам.

Идея:

```text
users
   ↓
group
   ↓
общие права доступа
````

Для группы можно установить разрешения на:

- чтение;
- запись.

Группы определяются в:

```
/etc/group
```

Каждая строка содержит поля:

```
group_name:password:GID:members
```

Основные элементы:

1. название группы;
2. поле пароля группы;
3. GID — идентификатор группы;
4. список дополнительных участников.

Пользователь также имеет основную группу, определяемую через GID в `/etc/passwd`.

# getty и login

После запуска системы необходимо предоставить пользователю возможность войти.

Для этого используются механизмы:

```
getty
   ↓
приглашение для входа
   ↓
login
   ↓
аутентификация
   ↓
пользовательский сеанс
```

`getty` предоставляет интерфейс для входа пользователя.

После ввода имени пользователя запускается `login`, который участвует в создании пользовательского сеанса.

# Идентификация, аутентификация и авторизация

Многопользовательская система должна решать три разные задачи.

## Идентификация

Вопрос:

```
Кто этот пользователь?
```

Например:

```
username ↔ UID
```

---

## Аутентификация

Вопрос:

```
Может ли пользователь доказать,
что он является тем, кем назвался?
```

Например, с помощью пароля.

---

## Авторизация

Вопрос:

```
Что этому пользователю разрешено делать?
```

Например:

- читать файл;
- изменять файл;
- запускать программу;
- получать дополнительные права.

---

## Что знает ядро

Ядро Linux в основном работает с:

```
числовыми UID
```

и идентификаторами владельцев файлов и процессов.

Ядро не занимается знанием:

```
имён пользователей
паролей
```

Эта информация относится преимущественно к пользовательскому пространству.

## Библиотеки получения информации о пользователях

Программе не нужно вручную каждый раз читать `/etc/passwd`.

Для типичных операций существуют стандартные библиотеки.

Например, функция:

```
getpwuid()
```

может использоваться для получения информации о пользователе по идентификатору.

Такой подход позволяет изменить источник информации о пользователях без изменения всех программ.

Например, вместо локального:

```
/etc/passwd
```

может использоваться внешняя служба пользователей.

Главная идея:

```
application
      ↓
standard library
      ↓
configured user information source
```
