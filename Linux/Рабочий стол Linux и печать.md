## 1. Из чего состоит графическая система

Основой графического вывода является **фреймбуфер** — область памяти, которую графическое оборудование считывает для формирования изображения на экране.

Поверх него работают компоненты графической системы:

```
Приложения
    │
    ▼
графические библиотеки / toolkit
    │
    ▼
оконная система
    │
    ▼
фреймбуфер
    │
    ▼
дисплей
```

Linux не имеет единственной обязательной настольной среды. Распространены:

```
GNOME
KDE
Xfce
```

Для построения интерфейсов используются toolkit, например:

```
GTK+
Qt
```

## 2. X Window и Wayland

### X

В системе X существует **X-сервер**, который управляет:

- дисплеями;
- визуализацией;
- устройствами ввода.

Приложения выступают как X-клиенты и взаимодействуют с сервером.

```
X client
   │
   ▼
X server
   │
   ├── keyboard
   ├── mouse
   ├── display
   └── framebuffer
```

X-сервер может обслуживать несколько мониторов как один `display`.

Пример:

```
:0
```

Процессы получают идентификатор дисплея через:

```
DISPLAY
```

### Wayland

Wayland устроен более децентрализованно.

Приложение получает собственный буфер, а **композитный менеджер** объединяет буферы приложений и формирует итоговое изображение.

```
Application A ──► buffer A ─┐
Application B ──► buffer B ─┼──► compositor ──► framebuffer
Application C ──► buffer C ─┘
```

В отличие от X, Wayland — это протокол взаимодействия между клиентом и композитным менеджером.

Переменная:

```
WAYLAND_DISPLAY
```

позволяет определить Wayland-сеанс. Например:

```
wayland-0
```

указывает на использование Wayland.

## 3. `libinput`, Xwayland и D-Bus

`libinput` работает с устройствами ввода ядра:

```
/dev/input
```

Например:

```
libinput list-devices
```

показывает устройства.

А:

```
libinput debug-events --show-keycodes
```

позволяет наблюдать события клавиатуры и других устройств.

**Xwayland** используется для запуска X-приложений в среде Wayland. Это X-сервер, работающий как клиент Wayland.

```
Wayland compositor
       │
       ▼
   Xwayland
       │
       ▼
   X application
```

Это позволяет старым X-приложениям работать в Wayland-сеансе.

**D-Bus** используется для межпроцессного взаимодействия и уведомления программ о событиях системы. Например, процессы могут регистрироваться в `dbus-daemon` для получения определённых событий.

## 4. Диагностика X и печать

Для исследования X книга приводит:

```
xwininfo
```

получение информации о выбранном окне;

```
xlsclients -l
```

список X-клиентов;

```
xev
```

просмотр событий X;

```
xinput --list
```

список устройств ввода.

`xev`, например, позволяет увидеть `KeyPress`, `KeyRelease`, `MotionNotify` и другие события.

Для печати рассматривается **CUPS**:

```
cupsd
```

— сервер печати.

Для передачи задания можно использовать:

```
lpr
```

CUPS поддерживает:

```
IPP — Internet Print Protocol
```

по TCP-порту:

```
631
```
