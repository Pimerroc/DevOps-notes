## 1. Файлы запуска оболочки и формирование окружения

Файлы запуска определяют, **как ведёт себя система при входе пользователя** и какие значения по умолчанию получают оболочка и интерактивные программы.

Их часто называют **dotfiles**, поскольку имена обычно начинаются с `.`:

```
.bashrc
.bash_profile
.profile
```

Большинство таких файлов создаются программами автоматически, но именно файлы запуска оболочки пользователь чаще всего изменяет вручную.

Главные принципы при создании файлов запуска:

- **простота** — файлов должно быть немного, а сами они должны быть короткими;
- **читаемость** — важные части должны иметь комментарии.

Чем больше элементов находится в файле запуска, тем больше потенциальных проблем он создаёт. Поэтому не стоит добавлять туда каждую настройку только ради удобства.

## 2. `PATH`, `MANPATH`, `PS1`, alias и `umask`

### `PATH`

Один из важнейших элементов пользовательского окружения — путь поиска исполняемых файлов.

Книга приводит минимальный порядок:

```
/usr/local/bin
/usr/bin
/bin
```

Порядок имеет значение: программы из `/usr/local/bin` имеют приоритет над системными версиями.

Для собственных программ можно использовать:

```
$HOME/bin
```

В книге также отмечается современный вариант:

```
$HOME/.local/bin
```

Для системных утилит могут потребоваться:

```
/usr/local/sbin
/usr/sbin
/sbin
```

Добавлять `.` в `PATH` не рекомендуется. Это создаёт потенциальную проблему безопасности: программа из текущего каталога может быть запущена вместо ожидаемой системной команды.

### `MANPATH`

Раньше путь к страницам руководства задавался через:

```
MANPATH
```

Но книга рекомендует не устанавливать его без необходимости, поскольку системные значения уже определяются через:

```
/etc/manpath.config
```

### `PS1`

`PS1` задаёт обычное приглашение Bash.

Пример из книги:

```
PS1='\u\$ '
```

Основные подстановки:

```
\u   имя пользователя
\h   имя хоста
\!   номер команды в истории
\w   текущий каталог
\W   последний компонент текущего каталога
\$   $ для обычного пользователя и # для root
```

Книга рекомендует не делать prompt чрезмерно сложным и не помещать в него символы, имеющие специальное значение для оболочки, например:

```
{ } = & < >
```

Особенно нежелателен `>`, поскольку он является оператором перенаправления.

### Alias

Псевдоним заменяет одну строку на другую перед выполнением команды.

Они удобны как короткие имена, но имеют недостатки:

- неудобно передавать аргументы;
- источник alias может быть неочевиден;
- alias не используется в подоболочках и не передаётся дочерним оболочкам.

Поэтому книга предлагает по возможности использовать **функции оболочки или отдельные сценарии**, а не большое количество alias.

### `umask`

`umask` задаёт маску прав доступа для новых файлов.

Книга приводит два варианта:

```
umask 077
```

Очень строгий вариант: другие пользователи не получают доступа к новым файлам и каталогам.

```
umask 022
```

Другим пользователям разрешается чтение новых файлов и каталогов.

Выбор зависит от того, предполагается ли совместное использование файлов.

## 3. Bash: login и non-login оболочки

Это одна из наиболее важных частей главы.

Интерактивные Bash-оболочки разделяются на:

```
login shell
non-login shell
```

### Login shell

Это начальная оболочка пользователя.

Она может появиться после обычного входа или удалённого входа через SSH.

Проверить её можно:

```
echo $0
```

Если первый символ результата — `-`, оболочка является login shell.

При запуске Bash как login shell:

```
/etc/profile
     ↓
первый найденный из:
.bash_profile
.bash_login
.profile
```

Важно: Bash запускает **только первый найденный** пользовательский файл из этой последовательности.

### Non-login shell

Обычная интерактивная оболочка, запущенная после входа.

Например, терминальные приложения обычно запускают именно её.

Bash читает:

```
/etc/bash.bashrc
        ↓
~/.bashrc
```

Поэтому `.bashrc` особенно важен для терминальной работы.

### Упрощённая схема

```
                 Bash
                   │
          ┌────────┴────────┐
          │                 │
       login            non-login
          │                 │
          ▼                 ▼
 /etc/profile       /etc/bash.bashrc
          │                 │
          ▼                 ▼
.bash_profile       ~/.bashrc
.bash_login
.profile
```

## 4. Практический `.bashrc` и типичные ошибки

Книга приводит компактный пример файла запуска:

```
# Command path.
PATH=/usr/local/bin:/usr/bin:/bin:/usr/games
PATH=$HOME/bin:$PATH

PS1='\u\$ '

EDITOR=vi
VISUAL=vi

PAGER=less
LESS=meiX

export PATH EDITOR VISUAL PAGER LESS

umask 022
```

Здесь одновременно задаются:

- `PATH`;
- prompt;
- редактор;
- pager;
- параметры `less`;
- экспорт переменных;
- `umask`.

`.bash_profile` можно сделать ссылкой на `.bashrc` либо явно подключать `.bashrc`:

```
. $HOME/.bashrc
```

Для различения интерактивной и неинтерактивной оболочки книга приводит проверку `$-`:

```
case $- in
    *i*)
        # интерактивные команды
        ;;
    *)
        # неинтерактивные команды
        ;;
esac
```

### Чего не следует делать

В файлах запуска не рекомендуется:

- запускать графические команды;
- устанавливать `DISPLAY`;
- устанавливать тип терминала;
- выполнять команды, выводящие данные в `stdout`;
- помещать слишком сложную логику;
- устанавливать `LD_LIBRARY_PATH`.

Последний пункт особенно важен: книга отдельно связывает его с проблемами разделяемых библиотек.
