## Роль сетевого уровня

Современное межсетевое взаимодействие основано прежде всего на:

```
IPv4
IPv6
```

Сетевой уровень должен быть программно независимым от конкретного оборудования и операционной системы.

Это означает, что IP-пакеты можно отправлять и получать:

- через различное оборудование;
- с использованием различных операционных систем.

---

## Интернет состоит из подсетей

Топология интернета децентрализована.

Интернет состоит из множества небольших сетей, называемых **подсетями** (`subnets`).

Все подсети каким-либо образом связаны друг с другом.

Например, обычная LAN обычно представляет собой одну подсеть.

---

## Маршрутизатор

Хост может быть подключён сразу к нескольким подсетям.

Если он способен передавать данные из одной подсети в другую, он называется:

```
маршрутизатор
router
```

Также используется название:

```
шлюз
gateway
```

---

## IPv4-адрес

IPv4-адрес имеет вид:

```
a.b.c.d
```

Например:

```
10.23.2.37
```

Технически IPv4-адрес состоит из:

```
4 байт
=
32 бита
```

Компьютер работает с адресом как с набором байтов.

Однако человеку удобнее использовать десятичную запись с точками:

```
10.23.2.37
```

а не внутреннее представление вроде:

```
0x0A170225
```

---

## Аналогия с почтовым адресом

IP-адрес можно приблизительно сравнить с почтовым адресом.

Однако для сетей важен не только адрес отдельного хоста.

Необходимо также понимать:

```
к какой подсети принадлежит хост
```

Для этого используется:

- маска подсети;
- или запись CIDR.

---

## Подсеть

Подсеть позволяет разделить IP-адрес на две логические части:

```
┌──────────────────┬──────────────┐
│ Часть сети       │ Часть хоста  │
└──────────────────┴──────────────┘
```

Часть сети определяет подсеть.

Часть хоста определяет конкретный хост внутри этой подсети.

---

## CIDR

Для обозначения размера сетевой части используется нотация CIDR.

Например:

```
10.23.2.37/24
```

Число:

```
/24
```

указывает длину сетевой части адреса.

В главе эта нотация используется вместе с обсуждением распространённых масок подсети и размеров сетей.

Основная идея заключается в том, что IP-адрес сам по себе не всегда достаточно полно описывает положение хоста в сети — необходима информация о подсети.
