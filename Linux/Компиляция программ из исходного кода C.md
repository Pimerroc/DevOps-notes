## 1. Общий процесс сборки

Типичный пакет исходного кода проходит примерно такую последовательность:

```
исходный код
     │
     ▼
распаковка
     │
     ▼
./configure
     │
     ▼
Makefile
     │
     ▼
make
     │
     ▼
make install
```

Задача `configure` — проверить особенности системы и подготовить файлы сборки.

Пакеты с Autoconf обычно содержат:

```
configure
Makefile.in
config.h.in
```

После:

```
./configure
```

создаются, среди прочего:

```
Makefile
config.h
config.cache
```

После этого запускается:

```
make
```

Успешный `configure`, однако, не гарантирует успешную компиляцию.

---

## 2. `configure` и `--prefix`

По умолчанию установка Autoconf-пакета обычно использует:

```
/usr/local
```

То есть:

```
/usr/local/bin
/usr/local/lib
...
```

Изменить место установки можно:

```
./configure --prefix=new_prefix
```

Также используются параметры:

```
--bindir=directory
--sbindir=directory
--libdir=directory
--disable-shared
--with-package=directory
```

## 3. Важные цели `make`

Помимо `all` и `install`, книга рассматривает:

```
make clean
```

удаляет объектные файлы, исполняемые файлы и библиотеки.

```
make distclean
```

возвращает исходное дерево к состоянию, близкому к только что распакованному архиву, удаляя также автоматически созданные файлы.

```
make check
```

запускает тесты пакета.

```
make install-strip
```

устанавливает программы без таблиц символов и другой отладочной информации.

## 4. `config.log` и диагностика

Если `configure` завершился ошибкой, важнейшим источником информации является:

```
config.log
```

Файл может быть очень большим.

Книга рекомендует перейти в конец:

```
less config.log
G
```

а затем искать проблему в обратном направлении, ориентируясь на сообщения `configure` вроде:

```
for more details
```

Таким образом:

```
configure error
       ↓
   config.log
       ↓
   найти последнюю ошибку
       ↓
   определить отсутствующую
   библиотеку / функцию / инструмент
```
