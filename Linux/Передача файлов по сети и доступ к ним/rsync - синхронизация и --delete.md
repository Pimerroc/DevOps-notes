По умолчанию `rsync` не делает целевой каталог точной копией источника.

Например:

```
Источник:

d/
 ├── a
 └── b
```

Если на целевой машине уже существует:

```
d/c
```

то после обычного копирования будет:

```
d/
 ├── a
 ├── b
 └── c
```

Для создания точной копии используется:

```
--delete
```

Например:

```
rsync -a --delete dir host:dest_dir
```

В этом случае файлы, отсутствующие в источнике, могут быть удалены из целевого каталога.

---

## Важное предупреждение

`--delete` потенциально опасен.

Перед использованием рекомендуется:

```
-nv
```

чтобы сначала увидеть, что именно произойдёт.

---

## Исходный каталог и косая черта

Эти две команды имеют разное значение:

```
rsync -a dir host:dest_dir
```

и:

```
rsync -a dir/ host:dest_dir
```

Без завершающей `/`:

```
копируется сам каталог dir
```

Получается:

```
dest_dir/dir/a
dest_dir/dir/b
```

С завершающей `/`:

```
копируется содержимое dir
```

Получается:

```
dest_dir/a
dest_dir/b
```

Эта разница особенно важна при использовании вместе с:

```
--delete
```

Автоматическое добавление `/` оболочкой при заполнении имени каталога также может неожиданно изменить поведение команды.
