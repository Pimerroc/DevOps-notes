## Запуск службы по запросу

Одна из возможностей systemd — не запускать службу заранее.

Вместо этого её можно запустить только тогда, когда она действительно понадобится.

Общая схема:

```text
Service Unit A
       ↑
       │
Resource Unit R
````

Процесс:

1. создаётся юнит службы `A`;
2. определяется ресурс, необходимый службе;
3. создаётся юнит ресурса `R`;
4. systemd отслеживает ресурс;
5. кто-то пытается использовать ресурс;
6. systemd активирует службу;
7. служба получает управление ресурсом.

Ресурс может быть представлен различными юнитами:

```
socket unit
path unit
device unit
```

Схема:

```
resource becomes active
        ↓
systemd detects access
        ↓
systemd starts service
        ↓
service takes control
```

Это позволяет откладывать запуск службы.

---

## Параллельный запуск

Если несколько компонентов не зависят друг от друга, systemd может запускать их одновременно.

Однако большое количество одновременно запускаемых юнитов может временно замедлить систему из-за высокой нагрузки.

Поэтому:

```
параллельность
≠
всегда более высокая мгновенная производительность
```

---

## Вспомогательные компоненты systemd

systemd включает или взаимодействует с рядом системных служб.

Примеры:

```
systemd-udevd
```

— обработка устройств.

```
journald
```

— ведение системного журнала.

```
resolved
```

— кэширование службы имён для DNS.

## Начальная файловая система оперативной памяти

Перед полноценным запуском основной системы может использоваться:

```
initrd
```

или начальная файловая система оперативной памяти.

Она загружается загрузчиком перед запуском полноценной рабочей среды Linux.

Общая идея загрузки:

```
bootloader
      ↓
kernel
      +
initrd
      ↓
начальная среда
      ↓
основная система
      ↓
init / systemd
```

Начальная файловая система необходима как промежуточная среда между запуском ядра и запуском основной системы.

---

## Завершение работы

При выключении система должна:

1. остановить службы;
2. упорядоченно завершить работу процессов;
3. завершить работу системы.

Это противоположная сторона процесса запуска:

```
boot:
kernel → init → services

shutdown:
services → init/system manager → kernel halt
```

## Аварийная загрузка

Если обычный запуск системы невозможен, используются специальные режимы загрузки.

Однопользовательский режим предназначен для обслуживания и восстановления системы, когда нормальная многопользовательская среда не может быть запущена.
