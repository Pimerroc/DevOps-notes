## Основная модель systemd

`systemd` — современная реализация `init`.

Её важное отличие от традиционной системы init заключается в расширенном управлении службами.

systemd может:

- отслеживать отдельные демоны после запуска;
- группировать процессы, относящиеся к одной службе;
- запускать независимые задачи без жёсткой последовательности;
- работать с зависимостями;
- реагировать на системные события.

Основная единица работы systemd:

```text
unit
````

Юнит представляет конкретную системную функцию.

При включении юнита происходит его:

```
activation
```

## Типы юнитов

Наиболее важные типы:

### Service unit

```
*.service
```

Управляет служебным демоном.

Примерная идея:

```
service
   ↓
daemon
```

---

### Target unit

```
*.target
```

Группирует другие юниты.

Целевой юнит представляет более высокоуровневое состояние или задачу системы.

При загрузке активируется:

```
default.target
```

Он, в свою очередь, активирует связанные с ним юниты.

---

### Socket unit

```
*.socket
```

Представляет ресурс для входящих подключений.

Используется, в частности, для запуска службы при необходимости.

---

### Mount unit

```
*.mount
```

Управляет подключением файловых систем.

---

## Граф зависимостей

Зависимости systemd не образуют простую последовательность:

```
A → B → C → D
```

Они образуют граф.

Например:

```
        A
       / \
      B   C
       \ /
        D
```

Юнит может зависеть сразу от нескольких других юнитов.

При активации юнита systemd пытается активировать его зависимости.

При этом systemd не обязана придерживаться строгой последовательности.

Если юниты готовы к запуску и не блокируют друг друга зависимостями, они могут запускаться независимо.

Граф зависимостей можно создавать с помощью:

```
systemd-analyze dot
```

## Конфигурация systemd

Основные каталоги:

```
/lib/systemd/system
```

или:

```
/usr/lib/systemd/system
```

Это каталог системных юнитов.

Локальная конфигурация обычно находится в:

```
/etc/systemd/system
```

Важное правило:

```
/usr и /lib
    ↓
файлы, управляемые дистрибутивом

/etc
    ↓
локальные изменения администратора
```

Поэтому не следует изменять файлы в каталоге системных юнитов.

Локальные изменения нужно выполнять в:

```
/etc/systemd/system
```

## Конфигурация как система зависимостей

Юнит не обязательно существует изолированно.

Его работа определяется:

```
сам юнит
   +
зависимости
   +
порядок активации
   +
целевые юниты
```

Именно поэтому systemd лучше рассматривать не как последовательность сценариев, а как:

```
граф ресурсов и задач
```
