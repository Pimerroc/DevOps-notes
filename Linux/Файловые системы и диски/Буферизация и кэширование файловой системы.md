Linux не обязательно сразу записывает изменения на физический диск.

При записи процесс сначала изменяет данные, которые могут находиться в **оперативной памяти**:

```text
process
   │
   ▼
kernel
   │
   ▼
RAM / filesystem cache
   │
   │ позже
   ▼
disk
```

Это повышает производительность, поскольку множество мелких операций можно объединить перед фактической записью на устройство.

### `sync`

Принудительно синхронизирует изменения с дисками:

```bash
sync
```

При `umount` ядро также синхронизирует необходимые данные перед отключением файловой системы.

Если систему невозможно корректно завершить обычным способом, перед выключением рекомендуется выполнить:

```bash
sync
```

### Кэширование чтения

Кэш работает и в обратную сторону. Если файл уже был прочитан с диска и его данные остались в RAM, повторное чтение может выполняться из памяти:

```text
первое чтение:
disk → RAM → process

повторное чтение:
RAM → process
```

Таким образом, файловый кэш одновременно уменьшает количество операций записи и чтения физического накопителя.
