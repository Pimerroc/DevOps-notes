### `df` — использование файловой системы

```bash
df
```

показывает использование смонтированных файловых систем:

```text
Filesystem  1K-blocks  Used  Available  Use%  Mounted on
/dev/sda1   214234312  ...   ...        63%   /
```

Основные поля:

- `Filesystem` — устройство/ФС;
- `1K-blocks` — общая ёмкость;
- `Used` — занято;
- `Available` — доступно;
- `Use%` — процент использования;
- `Mounted on` — точка монтирования.

Полезные варианты:

```bash
df -h
df -m
df -k
```

Если нужно узнать, на какой ФС находится конкретный каталог:

```bash
df /home/max
```

### Зарезервированные блоки

У ext-файловых систем часть пространства может быть зарезервирована. В приведённом примере это 5%.

Эти блоки предназначены прежде всего для суперпользователя и позволяют системе продолжать работу, когда обычное свободное пространство практически закончилось.

### `du` — кто занимает место

`df` отвечает:

> Сколько места занято на файловой системе?

`du` отвечает:

> Какие каталоги и файлы занимают это место?


Например:

```bash
du
du -s
du -s *
```

`du -s` выводит итоговый размер, а `du -s *` позволяет оценить содержимое текущего каталога. Скрытые каталоги при использовании `*` не учитываются.

### `fsck` — проверка файловой системы

`fsck` проверяет внутреннюю согласованность файловой системы:

```bash
fsck /dev/sdb1
```

Для ext2/ext3/ext4 обычно используется специализированная программа `e2fsck`, которую `fsck` запускает автоматически.

**Нельзя запускать `fsck` на нормально смонтированной файловой системе**, поскольку ядро может одновременно изменять её структуру, что приведёт к несогласованности и потенциальному повреждению данных.

При проверке ext-серии выполняются, среди прочего:

```text
Pass 1 → inode, blocks, sizes
Pass 2 → структура каталогов
Pass 3 → связи каталогов
Pass 4 → reference counts
Pass 5 → информация о группах
```

Если обнаружен inode, на который нет имени в дереве каталогов, `fsck` может поместить его в:

```text
lost+found/
```

с числовым именем.

### Безопасная предварительная проверка

Если есть подозрение на проблему:

```bash
fsck -n /dev/sdb1
```

`-n` запрещает изменение файловой системы.

Для автоматического исправления типичных проблем используется, например:

```bash
e2fsck -p /dev/sdb1
```

### Повреждение суперблока

Если повреждён основной суперблок, можно использовать его резервную копию:

```bash
fsck -b <номер>
```

Если номер резервной копии неизвестен, можно посмотреть их с помощью:

```bash
mkfs -n /dev/sdb1
```

Ключ `-n` здесь критичен: он позволяет получить информацию без создания новой файловой системы.

### Тяжёлое повреждение

При серьёзных проблемах с диском возможны следующие стратегии:

- сделать полный образ устройства с помощью `dd`;
- смонтировать ФС только для чтения и скопировать доступные данные;
- использовать `debugfs` для низкоуровневого просмотра и извлечения файлов.

При восстановлении предпочтительно сначала сохранить максимум исходных данных и по возможности работать с копией/образом, чтобы не усугубить повреждение.
