# Раздел 1 — Назначение сценариев и их ограничения

## Что такое сценарий оболочки

Сценарий оболочки — это последовательность команд, выполняемых оболочкой.

Его основное назначение — автоматизация действий, которые иначе пришлось бы вручную выполнять в командной строке.

Сильная сторона сценариев оболочки — работа с:

- командами Unix;
- файлами;
- группами файлов;
- конвейерами;
- перенаправлением ввода и вывода.

---

## Ограничения

Сценарии оболочки подходят не для всех задач.

Если требуется:

- сложный анализ строк;
- большое количество повторяющихся арифметических вычислений;
- сложный доступ к базам данных;
- сложные структуры управления;
- большие функции и программы,

книга рекомендует рассмотреть:

```
Python
Perl
awk
C
```

Сценарии оболочки желательно сохранять относительно короткими.

Главная идея:

> shell scripts особенно полезны для автоматизации операций Unix и связывания существующих программ.

# Раздел 2 — Кавычки, литералы и расширение

Кавычки являются одним из наиболее важных элементов синтаксиса оболочки.

Они определяют, должна ли оболочка интерпретировать символы или передать их команде буквально.

---

## Без кавычек

Например:

``` bash
echo $100
```

может не вывести строку `$100` буквально.

Причина в том, что оболочка интерпретирует:

```
$1
```

как переменную первого аргумента.

---

## Одинарные кавычки

Одинарные кавычки:

```
'...'
```

используются для передачи литерального текста.

Оболочка не выполняет обычные замены внутри них.

Например, все символы между одинарными кавычками, включая пробелы, становятся одним параметром.

Это особенно важно, когда необходимо передать программе текст, содержащий специальные символы оболочки.

---

## Двойные кавычки

Двойные кавычки:

```
"..."
```

похожи на одинарные, но оболочка продолжает расширять переменные.

Пример:

```bash
echo "There is no * in my path: $PATH"
```

Здесь:

```
$PATH
```

расширяется, а:

```
*
```

не превращается в список файлов.

---

## Общая логика

```
Без кавычек
    → оболочка активно интерпретирует специальные символы

'Одинарные кавычки'
    → буквальный текст

"Двойные кавычки"
    → переменные расширяются, но некоторые другие
      интерпретации подавляются
```

# Раздел 3 — Специальные переменные

Сценарии получают аргументы через специальные переменные.

## Отдельные аргументы

```
$1
$2
$3
```

содержат аргументы сценария.

Пример:

```bash
#!/bin/sh

echo First argument: $1
echo Third argument: $3
```

Запуск:

```
./pshow one two three
```

даёт:

```
First argument: one
Third argument: three
```

---

## `shift`

Команда:

```
shift
```

удаляет текущий первый аргумент и сдвигает остальные.

Например:

```
до shift:

$1 → one
$2 → two
$3 → three

после shift:

$1 → two
$2 → three
```

---

## Количество аргументов: `$#`

Переменная:

```
$#
```

содержит количество аргументов.

Она особенно полезна вместе с `shift`.

Когда:

```
$# = 0
```

аргументов больше не осталось.

---

## Другие специальные переменные

В главе также рассматриваются:

```
$@  → все аргументы
$0  → имя сценария
$$  → ID процесса
$?  → код возврата последней команды
```

---

# Раздел 4 — Коды возврата и условия

## Код возврата

После выполнения команда возвращает код.

В обычной Unix-конвенции:

```
0       → успех
не 0    → неуспех или другое состояние
```

Последний код возврата доступен через:

```
$?
```

Однако ненулевой код не всегда означает ошибку.

Например, `grep`:

```
0 → совпадение найдено
1 → совпадение не найдено
2 → произошла реальная ошибка
```

Поэтому значение кода возврата необходимо понимать в контексте конкретной программы.

---

## `if`

Пример:

```
if [ $1 = hi ]; then
    echo 'The first argument was "hi"'
else
    echo 'The first argument was not "hi"'
fi
```

Важный момент: конструкция:

```
[ ... ]
```

связана с командой:

```
test
```

Команда `[` выполняет проверку условия и возвращает код возврата.

Именно этот код определяет, будет ли выполнена ветвь `then`.

---

## `elif`

Позволяет проверить несколько условий:

```
if ...
then
    ...
elif ...
then
    ...
else
    ...
fi
```

Выполняется только первое истинное условие.

---

## `&&`

```
command1 && command2
```

`command2` выполняется, если `command1` завершилась с кодом `0`.

---

## `||`

```
command1 || command2
```

`command2` выполняется, если первая команда вернула ненулевой код.

---

## Проверка файлов

Сценарии оболочки особенно хорошо подходят для проверки файлов.

Например:

```
[ -f file ]
```

проверяет, является ли `file` обычным файлом.

Основные проверки условий делятся на:

```
проверки файлов
проверки строк
арифметические проверки
```

# Раздел 5 — `case` и циклы

## `case`

`case` используется для сопоставления значения с несколькими вариантами.

Пример из книги:

``` bash
#!/bin/sh

case $1 in
    bye)
        echo Fine, bye.
        ;;
    hi|hello)
        echo Nice to see you.
        ;;
    what*)
        echo Whatever.
        ;;
    *)
        echo 'Huh?'
        ;;
esac
```

Логика:

1. значение `$1` сравнивается с вариантами;
2. при совпадении выполняются соответствующие команды;
3. `;;` завершает ветвь;
4. `esac` завершает конструкцию.

Можно использовать:

```
несколько вариантов через |
шаблон *
шаблон ?
```

Вариант:

```
*)
```

используется как значение по умолчанию.

---

## `for`

`for` является циклом «для каждого».

Пример:

```
for str in one two three four; do
    echo $str
done
```

Оболочка последовательно:

1. присваивает `str` первое значение;
2. выполняет тело цикла;
3. переходит к следующему значению.

---

## `while`

`while` повторяет команды, пока условие имеет успешный результат.

Для выхода можно использовать:

```
break
```

В главе также упоминается:

```
until
```

Он работает аналогично `while`, но завершает цикл при нулевом коде возврата.

Книга отмечает, что сложные и часто используемые циклы `while` и `until` могут быть признаком того, что задачу лучше выполнять на языке, более подходящем для программирования, например Python или `awk`.

# Раздел 6 — Подстановка команд и другие возможности сценариев

## Подстановка команд

Оболочка может использовать вывод одной команды внутри другой.

Для этого применяется:

```
$(command)
```

Например:

```bash
FLAGS=$(grep ^flags /proc/cpuinfo | sed 's/.*://' | head -1)
```

Последовательность:

```
grep
  ↓
sed
  ↓
head
  ↓
результат сохраняется в FLAGS
```

Подстановка команд позволяет:

- передавать вывод одной команды другой;
- сохранять результат команды в переменной.

---

## Не стоит использовать `$(ls)`

Книга отдельно предупреждает, что не следует использовать:

```
$(ls)
```

для получения списка файлов.

Если нужно работать с файлами по шаблону, оболочка может выполнить:

```
*
```

непосредственно.

Если необходимо обрабатывать результаты `find`, лучше использовать:

```
xargs
```

или:

```
find -exec
```

а не подстановку команд.

---

## Другие важные элементы главы

В главе также рассматриваются:

```
временные файлы
here-документы
basename
awk
sed
xargs
expr
exec
подоболочки
добавление файлов в сценарии
чтение пользовательского ввода
```

Эти инструменты позволяют сценариям соединять стандартные утилиты Unix в более сложные автоматизированные процессы.
