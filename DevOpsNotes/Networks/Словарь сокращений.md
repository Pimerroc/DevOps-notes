# Словарь сокращений — главы 1–4

> Источник: Таненбаум, Фимстер, Кузеролл. *Компьютерные сети*, 6-е изд. — главы 1–4 (стр. 26–411).
> Книга ведёт собственный «Список аббревиатур» на стр. 22 (105 сокращений) и обещает, что «каждая аббревиатура выделена жирным шрифтом и расшифрована» по ходу текста.
>
> **Эта заметка — то, чего в книге не хватает.** В графе «в книге» отмечено, где книга расшифровывает сокращение, а где **нет** и от читателя требуется знать его заранее.
> Подобных «немых» сокращений, встречающихся в проверяемых утверждениях, набралось **7** — они и есть главный источник недопонимания при чтении. Список — в конце заметки.

> В книге три разных написания высоты для MEO/LEO — в одном месте 10 000, в другом 500–1500, потому что границы поясов радиации «размыты». Ключевое для запоминания — **задержка**:

> [!tip]- Главная путаница главы 2
> **Бод ≠ бит/с.** Бод — это символы в секунду. Если один символ несёт 4 бита (QAM-16), то 2400 бод = 9600 бит/с. Именно поэтому модем V.32bis при 2400 бод тянет 9600 бит/с.

## «Немые» сокращения — чего книга не расшифровывает

Это главная находка при вычитке. Список сокращений на стр. 22 (105 позиций) обещает расшифровку по ходу текста, но часть сокращений используется **без пояснения**. Ниже — те, что встречаются в проверяемых утверждениях, а значит могут попасть в вопросы.

| Сокращение | Где мелькает | Расшифровка |
| --- | --- | --- |
| **ARQ** | гл. 3, протоколы 3–6 | Automatic Repeat reQuest — повтор по таймауту или по NAK. Книга даёт синоним **PAR** (стр. 276), но не сам ARQ |
| **HLR** | гл. 2, GSM | Home Location Register — «домашний» реестр, где абонент прописан |
| **VLR** | гл. 2, GSM | Visitor Location Register — «гостевой» реестр, пока абонент в гостях |
| **AAL5** | гл. 3, ADSL | ATM Adaptation Layer type 5 — слой адаптации ATM |
| **FCS** | гл. 4, кадры | Frame Check Sequence — 32-битный CRC в конце кадра |
| **Baud** | гл. 2, модемы | бод — символов в секунду |
| **CO** | гл. 2, телефонная сеть | Central Office — центральная станция |
| **ETSI, ICANN** | — | В главах 1–4 **вообще не встречаются**, хотя это главные органы стандартизации. Не приписывай их книге |

Правило, которое из этого следует: **увидев сокращение, которого нет в списке стр. 22, ищите его в тексте сами — автора можно не считать источником.** Все расшифровки выше собраны из контекста и стандартных спецификаций.

> [!note]- Что книга расшифровывает, хотя и не везде
> **SPE** (стр. 184) и **PDU** (стр. 304–305) входят в список «немых», но при первом употреблении рядом с ними стоит полная расшифровка. Проверяй по месту, а не по списку.
> А вот **ARQ** — реально нигде: книга пишет только **PAR**, а ARQ оставляет читателю.

## Пары, которые путают чаще всего

| Сбирка | Разница |
| --- | --- |
| **Бод** ↔ **бит/с** | бод = символы/с; бит/с = бод × бит на символ |
| **LLC** ↔ **MAC** | MAC — доступ к среде (ниже), LLC — логическая связь (выше) |
| **ATM** ↔ **AAL5** | ATM — транспорт с ячейками, AAL5 — слой адаптации, где живёт IP |
| **SONET** ↔ **SDH** | SONET — американский, SDH — рекомендации МСЭ; отличия в нюансах |
| **T1** ↔ **E1** | 24 канала / 1,544 Мбит/с против 32 каналов / 2,048 Мбит/с |
| **OC-3** ↔ **OC-3c** | три канала по 51,84 чередуются **против** одного потока 155,52 |
| **CRC** ↔ **FEC** | CRC обнаруживает и требует повтора, FEC исправляет на месте |
| **FDM** ↔ **TDM** ↔ **WDM** ↔ **CDM** | по частоте / по времени / по длине волны / по коду |
| **GEO** ↔ **LEO** | 270 мс задержки против единиц миллисекунд |
| **hidden terminal** ↔ **exposed terminal** | первое даёт коллизию, второе — потерю ёмкости |
| **uni / multi / broadcast** | один адресат / группа / все |

## Как этим пользоваться

1. Прочитай [[Глава 1]], выписывая каждое сокращение в эту таблицу.
2. Пройди тест из «Главы 1–3 — Тест и терминология».
3. Ошибки почти всегда будут одного из двух видов: **забыл расшифровку** либо **спутал две похожие аббревиатуры**. Второе важнее — см. таблицу пар выше.
4. Всё, что книга не расшифряет, в таблицу «Немые сокращения» добавлено здесь, и эти определения стоит выучить наизусть: проверка именно на них чаще всего и строится.
