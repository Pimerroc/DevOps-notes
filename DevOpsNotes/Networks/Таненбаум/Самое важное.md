### DNS — процесс поиска (стр. 685–687)

> «DNS представляет собой сочетание иерархической схемы именования с распределенной базой данных, реализующей эту схему. В первую очередь DNS служит для преобразования имен хостов в IP-адреса». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=685|стр. 685]]

> «Прикладная программа вызывает библиотечную процедуру (обычно это gethostbyname или ее аналог), передавая ей имя в качестве параметра. Этот процесс иногда называют оконечным распознавателем (stub resolver). Он отправляет запрос с именем локальному DNS-распознавателю, или, как его еще часто называют, локальному рекурсивному распознавателю (local recursive resolver)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=685|стр. 685]]

> «Сервер имен, отвечающий за определенную часть этой иерархии, при этом считается авторитетным сервером имен (authoritative name server) для этого домена». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=686|стр. 686]]

> «Локальный распознаватель обеспечивает продолжение процесса разрешения имен путем выдачи дальнейших итеративных запросов». — про рекурсивные и итеративные запросы, [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=686|стр. 686]]

> «Каждый запрос содержит 16-битный идентификатор транзакции; он копируется в ответ». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=686|стр. 686]]

> «Именно поэтому каждый элемент базы данных DNS […] содержит поле Time_to_live. Оно сообщает удаленным серверам имен, как долго хранить эту запись в кэше». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=687|стр. 687]]

> «Теперь многие рекурсивные распознаватели используют QNAME-минимизацию, при которой локальный распознаватель отправляет ту часть запроса, которую способен обработать соответствующий авторитетный сервер имен». — RFC 7816, [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=687|стр. 687]]

> «Отмечается растущая тенденция к использованию TCP в качестве транспортного протокола для DNS. Со временем это позволило системе DNS эффективно применять современные безопасные протоколы транспортного и прикладного уровней, такие как DNS поверх TLS (DNS-over-TLS, DoT) и DNS поверх HTTPS (DNS-over-HTTPS, DoH)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=687|стр. 687]]

### DNS — пространство имен и иерархия (стр. 688–692)

> «Весь интернет разделен на более чем 250 доменов верхнего уровня (top-level domains), каждый из которых охватывает множество хостов». — ICANN управляет иерархией с 1998 г., [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=688|стр. 688]]

> «Доменное имя, которое ищет хост […] обычно называют полностью квалифицированным доменным именем (Fully Qualified Domain Name, FQDN)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=690|стр. 690]]

> «Имена доменов нечувствительны к регистру символов: edu, Edu и EDU означают одно и то же. Длина отдельных компонентов имени может составлять до 63 символов, но длина полного имени не должна превышать 255». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=691|стр. 691]]

> «Структура доменов отражает не физическое строение сети, а логическое разделение между организациями и их внутренними подразделениями». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=692|стр. 692]]

### DNS — записи ресурсов (стр. 694–698)

> «Записи ресурса состоят из пяти частей […] Domain_name Time_to_live Class Type Value». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=694|стр. 694]]

Типы записей (илл. 7.4, стр. 695):

| Тип | Значение |
| --- | --- |
| SOA | начальная запись зоны |
| A | IPv4-адрес хоста (32-битное целое) |
| AAAA | IPv6-адрес хоста (128-битное целое) |
| MX | обмен почтой (приоритет + хост) |
| NS | сервер имен для домена |
| CNAME | каноническое имя (псевдоним) |
| PTR | указатель (обратный просмотр: IP → имя) |
| SPF | правила отправки почты |
| SRV | хост, предоставляющий службу |
| TXT | описательный текст (обычно SPF) |

> «Записи MX сообщают имя хоста, готового принимать электронную почту для указанного домена». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=695|стр. 695]]

> «Просмотр записи PTR, связывающей имя с соответствующим IP-адресом, называется обратным просмотром (reverse lookup)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=696|стр. 696]]

DNSSEC (стр. 696–697): записи **RRSIG** (подпись набора RRSET закрытым ключом сервера) и **DNSKEY** (открытый ключ); ключ подписан родительским сервером — цепочка доверия до корня.

Зоны (стр. 697–698): «пространство имен DNS разделено на непересекающиеся зоны»; пример файла зоны cs.vu.nl — илл. 7.5.

### HTTP — методы и коды (стр. 741–743)

> «Имена методов чувствительны к регистру символов, то есть метод GET существует, а метод get — нет». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=742|стр. 742]]

### Брандмауэры (стр. 844–847)

> «Брандмауэр работает как пакетный фильтр (packet filter). Он исследует каждый входящий и исходящий пакет. Пакеты, удовлетворяющие определенным критериям, пропускаются. Не сумевшие пройти проверку пакеты удаляются». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=845|стр. 845]]

> «Демилитаризованная зона (DeMilitarized Zone, DMZ) — это часть сети компании, которая находится за пределами периметра безопасности. Сюда допускаются все». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=845|стр. 845]]

> «Брандмауэры с контролем состояния соединений (statefull firewalls) сопоставляют пакеты с соединениями и используют поля TCP/IP-заголовков для отслеживания этих соединений». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=846|стр. 846]]

> «Следующим уровнем сложности […] является реализация брандмауэром шлюза прикладного уровня (application-level gateway). При этом брандмауэр просматривает содержимое пакетов, не ограничиваясь лишь TCP-заголовками». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=846|стр. 846]]

> «Сегодня многие сети имеют несколько уровней защиты, вплоть до отдельных брандмауэров для каждого хоста. Это самый простой пример эшелонированной защиты (defense in depth)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=847|стр. 847]]

### IDS (стр. 847–851)

> «Системы обнаружения вторжений (Intrusion Detection System, IDS) служат для обнаружения атак, в идеале еще до того, как атаки успеют причинить какой-либо урон». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=847|стр. 847]]

> «Хостовые системы обнаружения вторжений (Host-based IDS, HIDS) работают непосредственно на конечной точке […]. Сетевые системы обнаружения вторжений (Network IDS, NIDS), напротив, проверяют сетевой трафик некоторой группы компьютеров». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=847|стр. 847]]

### IPsec и VPN (стр. 911–917)

> «"Соединение" в контексте IPsec называется сопоставлением безопасности (Security Association, SA). Это симплексное соединение между двумя конечными точками, с которым связан специальный идентификатор защиты». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=912|стр. 912]]

> «В транспортном режиме (transport mode) заголовок IPsec вставляется сразу после заголовка IP. […] В режиме туннелирования (tunnel mode) весь IP-пакет вместе с заголовком вставляется внутрь нового IP-пакета с совершенно новым заголовком. […] Обычно это касается VPN». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=912|стр. 912–913]]

> «Заголовок AH не позволяет шифровать данные, так что в основном он применяется в случаях, когда нужна проверка целостности, но не требуется секретность». — Authentication Header, [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=913|стр. 913]]

### TLS (стр. 931–935)

> «В 1995 году компания Netscape Communications […] представила пакет безопасности SSL (Secure Sockets Layer — уровень защищенных сокетов). Теперь он называется TLS (Transport Layer Security — защита транспортного уровня)». — [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=931|стр. 931]]

SSL/TLS создаёт защищённое соединение между двумя сокетами и обеспечивает: 1) согласование параметров; 2) аутентификацию сервера клиентом; 3) конфиденциальную передачу; 4) защиту целостности (стр. 932).

Рукопожатие (илл. 8.49, стр. 933): 1) клиент — версия, предпочтения, нонс RA → 2) сервер — выбранные параметры, нонс RB → 3) сервер — цепочка сертификатов X.509 → 5) клиент — подготовительный ключ (premaster key, 384 бита), зашифрованный открытым ключом сервера → 6–9) смена шифра, конец подпротокола. Сеансный ключ вычисляется из подготовительного ключа и нонсов обеих сторон.

> «В 1996 году корпорация Netscape Communications направила SSL на стандартизацию в IETF. Результатом стал стандарт TLS. Он описан в RFC 5246». — TLS 1.2 — 2008, TLS 1.3 — 2018; HTTPS = HTTP поверх SSL/TLS, порт 443 вместо 80, [[Tanenbaum_E_Fimster_N_Uezeroll_D_Kompyuternye_seti_6_e_izd_Klassika.pdf#page=935|стр. 935]]

Передача данных (илл. 8.50, стр. 934–935): фрагментация до 16 Кбайт → сжатие → MAC (хеш с сеансным ключом) → шифрование → заголовок → TCP.
