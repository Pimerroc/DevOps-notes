## 5.1 Служба сетевого уровня (стр. 412–419)

Маршрутизатор принимает пакет целиком (store-and-forward), проверяет checksum, выбирает выходную линию (стр. 412–413). Требования к службе: независимость от технологии маршрутизаторов, единая адресация (стр. 413).

| | Дейтаграммы (интернет) | Виртуальные каналы (X.25, ATM) |
| --- | --- | --- |
| Установка | нет | требуется |
| Адресация | полный адрес в каждом пакете | короткий идентификатор VC |
| Состояние в маршрутизаторе | нет | запись на каждый канал |
| Отказ маршрутизатора | теряются пакеты в пути | обрываются все каналы через него |
| QoS и перегрузка | трудно | легко при резервировании |

Виртуальный канал — логическая запись в таблице, не физическая линия; номер VC заменяется на каждом шаге (как метки MPLS) (стр. 416–418).

## 5.2 Алгоритмы маршрутизации (стр. 419–445)

Свойства алгоритма: корректность, простота, надёжность, устойчивость, справедливость, эффективность. Неадаптивные (статические) vs адаптивные (стр. 419–422).

- **Принцип оптимальности** (стр. 422): участок оптимального пути оптимален; все оптимальные пути к адресату = **входное дерево** (sink tree) / DAG.
- **Дейкстра** (стр. 423–426): кратчайшие пути от узла, неотрицательные веса, временные → постоянные метки, O(n²).
- **Лавинная адресация** (стр. 426–427): по всем линиям кроме входной; ограничение — счётчик переходов, порядковые номера, возраст.
- **Вектор расстояний** (стр. 427–431): Беллман — Форд, RIP. Таблицы «адресат → расстояние + линия», обмен векторами. **Счёт до бесконечности**: плохие новости распространяются медленно, маршрутизатор не знает, что он сам в чужом пути; расщепление горизонта и poisoned reverse помогают плохо.
- **Состояние линий** (стр. 431–437): 1) HELLO соседям; 2) измерение стоимости; 3) пакет LSP (id, seq 32 бита, возраст, соседи); 4) рассылка лавиной; 5) локальная Дейкстра. Переполнение seq при раз в секунду — через 137 лет; поле возраста лечит перезагрузку; в LAN — назначенный маршрутизатор (DR). Так работают OSPF и IS-IS.

| | Вектор расстояний | Состояние линий |
| --- | --- | --- |
| Знание | расстояния от соседей | полная топология |
| Рассылка | весь вектор периодически | LSP при изменениях |
| Сходимость | медленная | быстрая |
| Проблемы | счёт до бесконечности | памяти и CPU больше |

- **Иерархическая маршрутизация** (стр. 437–438): 720 маршрутизаторов — 720 записей; 24 региона — 53; 8×9×10 — 25. Оптимум по Камоуну — Клейнроку: ln N уровней, ~e·ln N записей; плата — удлинение путей.
- **Широковещание** (стр. 438–441): копии каждому; multicast-список; лавина; **RPF** (принять только с линии к источнику — 23 пакета/5 переходов против 14/4 у дерева); связующее дерево.
- **Multicast** (стр. 441–444): плотные группы — лавина с отсечением ветвей (MOSPF, DVMRP); разреженные — дерево с корнем в ядре, JOIN (PIM SM).
- **Anycast** (стр. 444): пакет — ближайшему члену группы; корневые DNS, CDN, NTP.

## 5.3 Перегрузка (стр. 445–463)

Причина: нагрузка > возможности; потери ⇒ повторные передачи ⇒ обвал перегрузки (стр. 445–448). M/M/1: `T = (1/μ)/(1 − ρ)`; при ρ = 0,95 задержка 20 мкс вместо 1 мкс (×20), при 99 % — ×100 (стр. 446).

Методы (стр. 448–462): избыточная ёмкость; маршрутизация с учётом нагрузки; **управление допуском** (не пускать поток без ресурсов); **сброс нагрузки** (винная стратегия — старое для файлов, молочная — новое для реального времени); **формирование трафика**; **RED**; **ECN**; сдерживающие пакеты; обратное давление.

- **Дырявое ведро** — постоянная скорость без всплесков; **маркерное** — всплеск до размера ведра. Длительность всплеска: `S = B / (M − R)`; пример B = 9600 КБ, M = 125 МБ/с, R = 25 МБ/с ⇒ ~94 мс (стр. 455–456).
- **RED** (стр. 458–459): средняя длина очереди > порога ⇒ случайный сброс до заполнения буфера; случайность — сигнал именно быстрым отправителям.
- **ECN** (стр. 460–461): 2 бита в заголовке IP; пометка вместо сброса, получатель возвращает отправителю через подтверждение.

## 5.4 QoS и QoE (стр. 463–480)

Четыре параметра приложения: пропускная способность, задержка, **джиттер**, потери (стр. 463–465, илл. 5.27: телефонии нужна низкая задержка и джиттер; передаче файлов — высокая полоса). Требования строже ограничений сети: потерю лечит повтор, джиттер — буфер (стр. 465). **QoE** — то, что почувствовал пользователь, независимо от SLA (стр. 465).

Планирование пакетов (стр. 466–474):

| Алгоритм | Механизм |
| --- | --- |
| FIFO | порядок прихода; один поток может захватить всё |
| Приоритетный | низкие голодают |
| RR | не учитывает размер пакетов |
| **WFQ** | `F_i = max(A_i, F_{i−1}) + L_i/W`, сортировка по F_i, O(log N) |

WFQ: поток с весом W получает ≥ `R = W·C/Σw` (стр. 472–473). **DRR** — O(1) на пакет, применяется на высоких скоростях (стр. 474).

- **IntServ + RSVP** (стр. 474–476): резервирование на каждый поток по всему пути; точные гарантии, но состояние в маршрутизаторах — не масштабируется.
- **DiffServ** (стр. 477–480): классы без состояния; **DSCP** — 6 бит в поле Differentiated services; **EF** (RFC 3246) — минимум задержки; **AF** (RFC 2597) — 4×3 = 12 классов; BE. Граница проверяет профиль потока и понижает класс при превышении.

## 5.5 Межсетевое взаимодействие (стр. 480–492)

Сети различаются: адресация, максимальный пакет, QoS, ошибки, multicast, безопасность (стр. 481–483). Приёмы объединения: **туннелирование** (пакет заворачивается в payload другой сети — IPv6 в IPv4, multicast) (стр. 483–485).

**Фрагментация** (стр. 488–492): непрозрачная — сборка на хосте (IP): Identification, MF, Fragment offset (13 бит, единицы 8 байт ⇒ до 8192 фрагментов; длина фрагментов кроме последнего кратна 8). **Path MTU discovery**: бит DF, ICMP «фрагментация нужна», отправитель уменьшает пакет (стр. 490–491).

## 5.6 SDN (стр. 492–499)

Плоскость управления (логически централизованный контроллер, вычисляет пути) отделена от плоскости данных (коммутаторы match-action) (стр. 492–495). **OpenFlow**: таблица «совпадение → действие» по MAC/IP/порту; дальше — **RMT** и язык **P4** (программируемый конвейер обработки). **INT** — телеметрия по каждому пакету (задержка на участке); шифрование трафика ограничивает видимость (стр. 498–499).

## 5.7 Сетевой уровень интернета (стр. 499–552)

Интернет — набор AS, модель **best effort** (стр. 499–500). RFC 1958 (стр. 500): упрощать; один способ, не пять; модульность; без зашитых параметров; «лучшее — враг хорошего»; **строг при отправке, снисходителен при получении**; продумывать масштабируемость.

### IPv4 (стр. 501–505)

Заголовок 20 байт (+опции до 40): IHL (4 бита, слов по 32 бита, макс 15 ⇒ 60 Б), Differentiated services (6 бит DSCP + 2 бита ECN), Total length 16 бит (65 535), Identification / DF / MF / Fragment offset (13 бит, по 8 Б), TTL (8 бит, максимум 255 переходов), Protocol, Header checksum (пересчитывается на каждом узле), Source/Destination по 32 бита (см. [[Заголовки протоколов]]).

### IP-адреса и CIDR (стр. 505–519)

Адрес — 32 бита, принадлежит **интерфейсу**. Префикс/хост: `128.208.2.0/24`; маска = префиксные единицы; иерархия сводит таблицы к ~300 000 префиксов (стр. 505–507). **CIDR**: блок 194.24.0.0/19 делится на /21 (Кембридж, 2048), /20 (Оксфорд, 4096), /22 (Эдинбург, 1024); для внешнего мира — один анонс /19 (стр. 509–510). **Самый длинный совпадающий префикс** — точнее /22 поверх агрегата /19 (стр. 510).

Классы (до 1993, стр. 507–509): A 0/8+24, B 10/16+16, C 110/24+8, D 1110 multicast (224–239), E резерв. Проблема: B — 65 536 адресов, большинству много.

Особые: `127.x.y.z` loopback; `255.255.255.255` широковещание; `0.0.0.0` этот хост (стр. 513).

**NAT** (стр. 514–519): приватные 10/8, 172.16/12, 192.168/16; замена адреса **и порта** (до 61 440 устройств на адрес — 65 536 − 4096). Критика: ломает сквозной принцип, входящие соединения, протоколы с адресом в payload (FTP), независимость уровней.

### IPv6 (стр. 519–530)

IPv4-адреса кончились — последние блоки выделены 25.11.2019 (стр. 519). Адрес 128 бит (~3,4·10³⁸). Заголовок **40 байт**, 8 полей: Version, Differentiated services, Flow label, Payload length, Next header, Hop limit, адреса по 16 Б. Убраны: IHL, Protocol (→ Next header), поля фрагментации (фрагментирует только источник), **checksum**, опции (→ расширенные заголовки: Hop-by-hop, Routing, Fragment, Authentication, ESP). Минимальный MTU — 1280 Б (стр. 525). Запись: `::` вместо одной группы нулей, IPv4-хвост `::192.31.20.46` (стр. 527). Доля IPv6 ~25 %, переход через двухстековые хосты и туннели (стр. 529–530).

### ICMP, ARP, DHCP (стр. 530–535)

- **ICMP**: Destination unreachable, Time exceeded (TTL=0 — основа traceroute), Parameter problem, Redirect, Echo/reply (ping), Timestamp, Router advertisement (стр. 530–533).
- **ARP**: IP → MAC внутри LAN; широковещательный запрос, ответ кэшируется; gratuitous ARP — проверка дублирования адреса (стр. 533–534).
- **DHCP**: DISCOVER (широковещательно) → OFFER; адрес в аренду с продлением; передаёт маску, шлюз, DNS, NTP (стр. 534–535).

### MPLS (стр. 535–538)

Коммутация по **20-битной метке** (заголовок 32 бита: Label 20, QoS 3, S 1, TTL 8; стек меток). **LER** на границе (IP → метка), **LSR** внутри (замена метки). Пакеты одного пути и класса = **FEC**. «Уровень 2,5» (стр. 536–537).

### OSPF (стр. 538–544)

Link-state **IGP** внутри AS (IS-IS — у провайдеров). Области: область 0 — магистраль; **ABR** соединяет области, **ASBR** — с внешними AS; тупиковые области; **DR/BDR** в LAN. Сообщения: HELLO, Link State Update/ACK, Database Description, Link State Request. **ECMP** — несколько равных путей одновременно (стр. 540–541).

### BGP (стр. 544–551)

**EGP** между AS; цель — **политика**, не кратчайший путь. Экономика: транзит (клиент платит), безрасчётный пиринг, платный пиринг, multihoming. **Path vector**: анонс несёт **AS path**; своя AS в пути ⇒ петля, маршрут отвергнут. Порядок выбора: local preference → длина AS path → eBGP > iBGP → MED → IGP-cost до next hop. **Hot-potato** — ранний вывод трафика из своей AS ⇒ несимметричные маршруты (стр. 546–548).

### Multicast в интернете (стр. 551–552)

Класс D: 28 бит на группу (~250 млн). `224.0.0.1` все узлы LAN, `224.0.0.2` все маршрутизаторы, `224.0.0.5` OSPF, `224.0.0.251` mDNS. **IGMP** — членство хостов; **PIM**: Dense Mode (лавина с отсечением), Sparse Mode (rendezvous point), SSM (стр. 551–552).

## 5.8 Политика сетевого уровня (стр. 552–554)

Пиринговые споры: с 2013 крупные контент-провайдеры платят сетям доступа за прямое подключение (платный пиринг) (стр. 552–553). Сетевой нейтралитет — 4 правила: не блокировать, не замедлять, не вводить платную приоритизацию, не скрывать методы приоритизации; исключение — разумное управление сетью (стр. 553–554).
