## Оглавление главы

4.1 Проблема распределения канала (313) · 4.2 Протоколы коллективного доступа (317) · **4.3 Ethernet (336)** · **4.4 Беспроводные LAN 802.11 (358)** · 4.5 Bluetooth (376) · 4.6 DOCSIS (384) · 4.7 Коммутация на канальном уровне (386)

MAC определяет **очередность использования линии** (стр. 313). Канальный уровень разделён по признаку зависимости от среды: **LLC** — фрейминг, ошибки, поток, идентификация протокола (поле Type, граница 0x600 = 1536) — материал [[Глава 3]]; **MAC** — кто говорит следующим — эта глава (стр. 359–360). MAC-адрес идентифицирует **интерфейс**, не устройство: 24 бита OUI (IEEE) + 24 бита NIC; ноутбук с Ethernet+Wi-Fi+Bluetooth — три адреса (стр. 338–339).

**ARP** — канальный протокол, разрешает адрес только для соседа в том же широковещательном домене. IP-адрес не меняется на всём пути, MAC меняется на каждом хопе (адрес следующего узла). В IPv6 ARP заменён **NDP** поверх ICMPv6.

Хаб vs Wi-Fi — почему CD и CA (стр. 321–324, 364): в проводе можно слушать во время передачи (сравнение напряжения) ⇒ CSMA/**CD**; в радио приёмник «оглох» и области покрытия не совпадают ⇒ CSMA/**CA**.

## 4.1 Проблема распределения канала (стр. 313–317)

Статическое разбиение (FDM/TDM) даёт задержку в N раз хуже из-за простоя чужих подканалов:

```
T = 1 / (μC − λ)                      M/M/1
Пример: C = 100 Мбит/с, фрейм 10 000 бит, λ = 5000 фреймов/с → T = 200 мкс
Разбить на 10 подканалов → 2 мс
```

Пиковое отношение трафика ~1000:1 — статические схемы не годятся (стр. 313–315). Пять допущений анализа (стр. 315–317): независимый пуассоновский трафик N станций; единый канал; коллизия видна всем (в радио — нет, узнают по отсутствию ACK); время непрерывное или слотированное; контроль несущей есть/нет. Ни один протокол коллективного доступа не гарантирует надёжную доставку (стр. 317).

## 4.2 Протоколы коллективного доступа (стр. 317–336)

### ALOHA (стр. 317–321)

Чистая ALOHA (илл. 4.1–4.2): передавай сразу; уязвимый период 2t.

![[4.1.png]]
![[4.2.png]]

```
P₀ = e^(−2G)    S = G·e^(−2G)    S_max = 1/2e ≈ 0,184 при G = 0,5
```

Дискретная ALOHA (Робертс, 1972) (илл. 4.2): передача с начала слота.

```
P₀ = e^(−G)     S = G·e^(−G)     S_max = 1/e ≈ 0,368 при G = 1
37 % пусто / 37 % успех / 26 % коллизий; попытки E растут экспоненциально с G
```

### Контроль несущей (стр. 321–325)

| Протокол | Свободный канал | Занятый |
| --- | --- | --- |
| Настойчивость 1 | передаёт сразу | ждёт освобождения |
| Ненастойчивый | передаёт сразу | случайная пауза, потом снова слушает |
| Настойчивость p | передаёт с вероятностью p | ждёт слота |
| **CSMA/CD** | настойчивость 1 + обрыв при коллизии | двоичная экспоненциальная выдержка |

Коллизии у CSMA — из-за задержки распространения. Состояния CSMA/CD: передача / конкуренция / простой (илл. 4.5). Время захвата канала — **2τ** (конкуренция ≈ дискретная ALOHA со слотом 2τ); в коаксиале 1 км τ ≈ 5 мкс (стр. 324).

![[4.5.png]]

### Протоколы без коллизий (стр. 325–329)

- **Битовая карта** (илл. 4.6): N слотов конкуренции, станция j сигналит в слоте j; эффективность d/(d+N) при низкой и d/(d+1) при высокой нагрузке; среднее ожидание N слотов.

![[4.6.png]]
- **Передача маркера**: кольцо (802.5), логическое кольцо на шине (802.4, отменён), FDDI проиграла Ethernet, RPR = 802.17.
- **Двоичный обратный отсчёт** (Datakit, 1983): адрес побитно по ИЛИ; станция с 0 против суммы 1 сдаётся; выигрывает наибольший адрес; накладные log₂N.

### Ограниченная конкуренция (стр. 329–333)

```
P(успех) = k·p·(1 − p)^(k−1)      оптимум p = 1/k, k → ∞ ⇒ 1/e
Адаптивное дерево: старт с уровня i = log₂q, где q — готовые станции
```

Групповой арбитраж: группы по слотам, при росте станций группы мельчают (илл. 4.10 — дерево состязания).

![[4.10.png]]

### Скрытая и засвеченная станция; MACA (стр. 333–336)

**Скрытая** не слышит конкурента — оба сигнала гибнут у приёмника; **засвеченная** слышит мешающую ей передачу и молчит зря (илл. 4.11). **MACA** (Карн, 1990): A → RTS (30 байт, длина фрейма), B → CTS; услышавшие RTS (но не CTS) молчать не обязаны, услышавшие CTS молчат до конца приёма (илл. 4.12).

## 4.3 Ethernet (стр. 336–358)

Классический (3–10 Мбит/с, шина, CSMA/CD) — история; **коммутируемый** (100…100 000 Мбит/с) — сегодняшний стандарт.

### Физика и фрейм (стр. 337–341)

Меткалф и Боггс, Xerox 1976 (3 Мбит/с); DIX 1978 (10 Мбит/с); IEEE 802.3 — 1983. Толстый Ethernet: 500 м, 100 станций; тонкий: 185 м, 30. Повторители — физический уровень; максимум 2500 м и 4 повторителя; кодирование манчестерское (илл. 4.13).

Фрейм (илл. 4.15, см. [[Заголовки протоколов]]): преамбула 8 Б, адреса 6+6 Б (первый бит адреса получателя — групповой; все единицы — широковещание; первые 3 Б — OUI), Type/Length 2 Б, payload 0–1500 Б, Pad, checksum 4 Б (CRC-32).

**Минимальный фрейм 64 байта**: время передачи ≥ 2τ, иначе отправитель не узнает о коллизии; 512 бит при 10 Мбит/с = 51,2 мкс (стр. 339–340). Ошибки только обнаруживаются, фрейм отбрасывается.

![[4.15.png]]

### Экспоненциальная выдержка и производительность (стр. 342–344)

После i-й коллизии случайный интервал 0…2^i−1; потолок 1023 после 10 коллизий; сдаётся после 16 (стр. 343). Подтверждений нет — кабель надёжен.

```
Эффективность = 1 / (1 + 2e·B·L/(c·F))              (4.3)
```

При F = 1024 Б — 85 % (vs 37 % у ALOHA); накладные e·64 ≈ 174 байта на фрейм (стр. 344).

### Концентратор vs коммутатор (стр. 344–346)

Хаб соединяет порты электрически — одна область коллизий, CSMA/CD. Коммутатор — область коллизий на порт, при полном дуплексе коллизий нет.

### Fast / Gigabit / 10G / 40–100G (стр. 347–357)

Fast Ethernet (802.3u, 1995): тот же фрейм; 100Base-T4 (4 пары, cat 3), 100Base-TX (4B/5B, 2 пары), 100Base-FX (оптика, 2000 м).

| Вариант | Среда | Длина |
| --- | --- | --- |
| 1000Base-SX | многомод 0,85 мкм | 550 м |
| 1000Base-LX | одномод | 5000 м |
| 1000Base-T | cat 5, 4 пары | 100 м |
| 10GBase-SR / LR / ER | многомод / одномод 1,3 / 1,5 мкм | 300 м / 10 км / 40 км |
| 10GBase-T | cat 6a | 100 м |

Gigabit (802.3ab): полный дуплекс — норма; в полудуплексе — расширение носителя до 512 Б (эффективность 9 %) и пакетная передача фреймов; PAUSE-фрейм 0x8808 (пауза до 33,6 мс); джамбо-фреймы до 9 КБ (не в стандарте); код 8B/10B (стр. 350–353). 10G — только полный дуплекс, код 64B/66B (стр. 354–356). 40–100 Гбит/с — до 10 полос по 10 Гбит/с (стр. 356–357).

### Почему Ethernet выжил (стр. 357–358)

Простота · низкая цена · совместимость с IP (убила соединительный ATM) · рост скорости без смены ПО · заимствование лучших кодов (4B/5B у FDDI, 8B/10B у Fibre Channel).

## 4.4 Беспроводные LAN — 802.11 (стр. 358–376)

Инфраструктурный режим (клиенты через AP, распределительная сеть) и ad hoc (илл. 4.21). Стек: PHY → MAC → LLC (стр. 359–360).

Физический уровень (стр. 361–364): 2,4 и 5 ГГц, мощность до 1 Вт (на практике ~50 мВт).

| Стандарт | Диапазон | Скорость | Механизм |
| --- | --- | --- | --- |
| 802.11b | 2,4 ГГц | 1–11 Мбит/с | DSSS, Баркер, CCK |
| 802.11a | 5 ГГц | 6–54 Мбит/с | OFDM, 52 поднесущих |
| 802.11g | 2,4 ГГц | 6–54 Мбит/с | OFDM, совместим с b |
| 802.11n | 2,4+5 | ≥ 100 Мбит/с | 40 МГц, MIMO до 4×4 |
| 802.11ac | 5 ГГц | до 7 Гбит/с | 80/160 МГц, 256-QAM, MU-MIMO |
| 802.11ad | 60 ГГц | — | одна комната |
| 802.11ax (Wi-Fi 6) | до 7 ГГц | до 11 Гбит/с | OFDMA, 1024-QAM, TWT |

Радиус 11b ≈ в 7 раз больше 11a; алгоритм адаптации скорости стандарт не задаёт (стр. 362–363).

### MAC 802.11 (стр. 364–371)

Причины отказа от CSMA/CD (стр. 364): полудуплексный радиопередатчик (не слышит во время передачи) + несоответствие областей покрытия (скрытая станция).

**DCF**: DIFS → случайный отсчёт (0…15 слотов для OFDM) → передача при нулевом счётчике; занятый канал приостанавливает отсчёт (илл. 4.25). Отправка ⇒ ожидание ACK; нет ACK ⇒ удвоить интервал молчания. Отличия от Ethernet: коллизии предотвращаются, а не обнаруживаются; ACK обязателен. **PCF** (централизованное управление AP) на практике не применяется (стр. 365–366).

![[4.25.png]]

- **NAV** — виртуальное прослушивание: поле Duration (включая ACK) заставляет молчать без несущей; в 802.11ax — два NAV (свои и чужие сети) (стр. 366).
- **RTS/CTS** (илл. 4.27): лечит скрытую станцию; засвеченную — нет (все услышавшие RTS или CTS молчат ради ACK); из-за накладных применяется редко (стр. 366–367).

![[4.27.png]]
- **Надёжность**: при потерях понижение скорости + короткие фреймы `(1−p)^n` — при p = 10⁻⁴ фрейм 12 144 бита проходит с вероятностью < 30 %; фрагментация со своими CRC и подтверждениями (стр. 368).
- **Энергия**: маяки каждые ~100 мс, клиент дремлет, AP буферизует; APSD (2005) для VoIP (стр. 368–369).
- **QoS (802.11e)**: разные межфреймовые интервалы — порядок **SIFS < AIFS1 < DIFS < AIFS4**; EIFS — только после битого кадра (стр. 369–370).
- **TXOP**: равное время вместо равного числа фреймов — против аномалии скорости (6 и 54 Мбит/с обе получали бы 5,4 Мбит/с; с TXOP — 3 и 27) (стр. 370).

### Фрейм и службы (стр. 371–376)

Фрейм данных (илл. 4.29, см. [[Заголовки протоколов]]): Frame Control 2 Б (11 полей), Duration 2 Б, Address 1/2/3 по 6 Б (получатель, отправитель, конечная точка за AP), Sequence 2 Б, Data 0–2312 Б, FCS 4 Б.

![[4.29.png]]

Службы (стр. 373–375): сопоставление (association) с AP, пересопоставление, распределение, интеграция; SSID можно не передавать в маяках. Безопасность: WEP взломан 2002, WPA2 (AES) — 2017 (KRACK), WPA3 — 2018; слабое место — управление ключами; корпоративно — 802.1X + EAP (>50 методов).

## 4.5 Bluetooth (стр. 376–384)

Ericsson 1994; SIG 1998; 1.0 — 1999. **Пикосеть**: 1 главный + до 7 активных + до 255 запаркованных; главный передаёт в чётные слоты, подчинённые — в нечётные; прямой связи подчинённых нет; несколько пикосетей через узел-мост = **рассеянная сеть** (илл. 4.30) (стр. 376–377). Профили — 25 сценариев применения (стр. 377–378).

![[4.30.png]]

Стек (стр. 378–380): профили → L2CAP (сообщения до 64 КБ, мультиплексирование) + RFcomm (эмуляция COM-порта) → управление соединением → базовый канальный → радио. Граница **HCI** — ниже чип, выше устройство.

Радио (стр. 380–381): ISM 2,4 ГГц, **79 каналов по 1 МГц**, FHSS до **1600 скачков/с**, слот **625 мкс**, фреймы 1/3/5 слотов. Адаптивная перестройка исключает занятые каналы. Модуляция: 1 бит/символ = 1 Мбит/с, с 2.0 — 2–3 Мбит/с.

| | SCO | ACL |
| --- | --- | --- |
| Назначение | голос, реальное время | пакеты |
| Повторы | нет (FEC) | есть, best effort |
| У подчинённого | до 3 (64 Кбит/с PCM каждый) | 1 |

Фрейм (илл. 4.32): код доступа, заголовок 18 бит × 3 копии = 54 бита, данные. Эффективность ~13 % (стр. 382–383). Bluetooth 5 (2016): 2 Мбит/с, сообщения 255 Б, 40 м в помещении (стр. 383–384).

## 4.6 DOCSIS MAC (стр. 384–386)

- **Ranging** (пристрелка): CMTS измеряет задержку и задаёт мощность; по умолчанию раз в 30 с, обычно 10–20 с (стр. 385).
- **Service flows**: каждому модему — идентификаторы потоков с ограничениями (стр. 385–386).
- **Мини-слоты** с шагом **6,25 мкс** — единица QoS (стр. 386).
- **LLD** (Low-Latency DOCSIS): две очереди, планирование 2–4 мс → 1 мс (стр. 386).

## 4.7 Коммутация на канальном уровне (стр. 386–404)

**Мост = коммутатор**: смотрит только MAC-адреса, Payload не читает (стр. 387). Три причины нескольких LAN: подразделения; расстояния; ёмкость (две LAN = вдвое больше полосы) (стр. 387–388).

### Обучение и пересылка (стр. 388–391)

- Таблицы пусты ⇒ **лавинная адресация** (flooding) неизвестных адресов.
- **Обратное обучение**: адрес отправителя → порт; записи стареют за минуты.
- Алгоритм: порт-источник = порт-назначение → отбросить; известен порт назначения → переслать; неизвестен → flooding (илл. 4.33).

![[4.33.png]]
- Разные скорости портов ⇒ буферизация; **cut-through** — отправка после чтения адреса.

### Связующее дерево (стр. 391–394)

Циклы мостов зацикливают flooding. Алгоритм Перлман (IEEE 802.1D): мост с наименьшим идентификатором — корень; каждый считает кратчайший путь до корня и отключает прочие порты (илл. 4.36).

![[4.36.png]]

### Кто на каком уровне (стр. 394–397)

| Устройство | Уровень | Что видит |
| --- | --- | --- |
| Повторитель | физический | усиливает сигнал (4 повторителя: 500 → 2500 м) |
| Концентратор | физический | одна коллизионная область |
| Мост/коммутатор | канальный | MAC-адрес |
| Маршрутизатор | сетевой | IP-заголовок |
| Транспортный шлюз | транспортный | TCP ↔ SCTP |
| Шлюз приложений | прикладной | содержимое (email → SMS) |

Мосты разных типов LAN (Ethernet ↔ Token Ring) не сработали — разная максимальная длина фрейма; разные типы соединяют маршрутизаторы (стр. 396–397).

### VLAN и 802.1Q (стр. 397–404)

Зачем VLAN: безопасность; разделение нагрузки; ограничение широковещания (и защита от шторма) (стр. 398). Тег используется только мостами: первый VLAN-мост вставляет, последний удаляет — формат фрейма для конечных узлов не меняется; лимит фрейма 1518 → 1522 (стр. 399–400).

Тег 802.1Q — 4 байта: TPID **0x8100** (2 Б, > 1500 ⇒ читается как Type), Priority 3 бита, CFI 1 бит, VID **12 бит** (илл. 4.39–4.40) (стр. 400–401). Метка = индекс таблицы коммутатора: VLAN работает как сеть с соединением (стр. 402). Фрейм идёт только на порты с его меткой; порт между мостами может не иметь метки сегмента, где станции этой VLAN нет.
