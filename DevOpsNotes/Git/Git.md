### 1.
	Гит не хранит список изменений для файла как остальные СКВ (системы контроля версий), он сохраняет так называемые snapshot (Снaпшоты), некоторые снимки файла в текущей файловой системе, а с каждым комитом при отсутсвии изменений ссылается на предыдущий файл.

### 2. Три состояния
	Это самая важная вещь, которую нужно запомнить о Git. У Git есть три основных состояния, в которых могут находиться ваши файлы: изменён (modified), индексирован (staged) и зафиксирован (committed) :
	- К изменённым относятся файлы, которые поменялись, но ещё не были зафиксированы.
	- Индексированный — это изменённый файл в его текущей версии, отмеченный для включения в следующий коммит.
	- Зафиксированный значит, что файл уже сохранён в вашей локальной базе.

### 3. Работа с удаленной директорией
	Когда ты (клонируешь/загружаешь на) удаленный репозиторий Git создает отдельные ветки, которые следят за ветками в удаленных репозитория. Такие ветки обычно обозначаются origin/<branch name>, где origin -- имя сервера, на который пушиться (посмотреть можно через git remote -v), а branch name имя ветки в твоем локальном репозитории. Исполняя команду `git fetch origin`, мы получаем изменения с сервера именно в эту ветку! 
###  4. Относительные пути 
	В гит есть возможность перемещаться между ветками используя символы ~ и ^.
~n - перемещает HEAD/указатель относительно ветки/коммита назад на n коммитов
^ -- перемещает HEAD/указатель относительно ветки/коммита назад на на 1 родителя(их можно указывать много раз). В случае же если вы находитесь на развилке, можно выбрать родителей используя \^2 -- второй родитель, \^3 -- третий итд.
