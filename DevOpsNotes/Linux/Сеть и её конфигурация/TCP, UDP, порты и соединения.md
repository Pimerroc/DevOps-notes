## Транспортный уровень

Основными транспортными протоколами являются:

```
TCP
UDP
```

Транспортный уровень связывает сетевую передачу с конкретными службами и процессами.

---

# Порты

IP-адрес определяет хост.

Порт определяет конкретную службу или точку взаимодействия на хосте.

Аналогия:

```
IP-адрес
=
адрес здания

Порт
=
конкретная точка назначения внутри здания
```

---

## TCP-соединение

TCP использует комбинацию:

```
локальный IP
+
локальный порт
+
удалённый IP
+
удалённый порт
```

Например:

```
10.23.2.4:47626
        ↓
10.194.79.125:5222
```

Клиент обычно использует временный:

```
ephemeral port
```

а сервер ожидает подключения на известном порту.

---

## Прослушивание

Сервер ожидает входящие соединения на определённом порту.

Можно представить это так:

```
Клиент
IP:порт
   │
   │ TCP connection
   ▼
Сервер
IP:известный порт
```

# TCP

TCP предоставляет потоковую передачу данных.

Реализация TCP должна выполнять множество операций:

- разбивать поток данных;
- собирать данные на принимающей стороне;
- учитывать порядок пакетов;
- обнаруживать потерю пакетов;
- обнаруживать повреждения;
- исправлять последствия ошибок передачи.

Книга сравнивает TCP с:

```
телефонным разговором
```

# UDP

UDP проще TCP.

Он передаёт отдельные сообщения.

В отличие от TCP:

- UDP не предоставляет поток данных;
- UDP не исправляет потерянные пакеты;
- UDP не исправляет неупорядоченные пакеты;
- UDP не имеет соединений.

UDP использует порты, но один хост просто отправляет сообщение со своего порта на порт другого хоста.

Получатель может ответить, если это необходимо.

UDP способен обнаруживать повреждение данных в пакете, но не исправляет его.

Книга сравнивает UDP с:

```
письмом
телеграммой
мгновенным сообщением
```

Приложения используют UDP, когда хотят отправлять сообщения как можно быстрее и не хотят использовать более сложный механизм TCP.
