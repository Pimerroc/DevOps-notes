Полноценная сеть состоит из набора сетевых уровней.

Этот набор называется **сетевым стеком** (`network stack`).

В книге используется стек из четырёх уровней:

```
┌──────────────────────────────┐
│ Прикладной уровень           │
├──────────────────────────────┤
│ Транспортный уровень         │
├──────────────────────────────┤
│ Сетевой / межсетевой уровень │
├──────────────────────────────┤
│ Физический уровень           │
└──────────────────────────────┘
```

---

## 1. Прикладной уровень

Прикладной уровень (`application layer`) содержит язык и протоколы, которые приложения и серверы используют для общения.

Примеры:

- HTTP;
- TLS;
- FTP.

Протоколы прикладного уровня могут объединяться.

Например:

```
HTTP + TLS = HTTPS
```

Обработка прикладного уровня происходит в **пользовательском пространстве**.

---

## 2. Транспортный уровень

Транспортный уровень (`transport layer`) определяет характеристики передачи данных прикладного уровня.

Он включает:

- проверку целостности данных;
- порты источника;
- порты назначения;
- разбиение данных приложения на пакеты;
- повторную сборку данных на стороне назначения.

Основные протоколы:

```
TCP
UDP
```

Этот уровень иногда называют уровнем протокола.

В Linux транспортный уровень и нижележащие уровни в основном обрабатываются **ядром**, хотя в некоторых случаях пакеты могут передаваться в пользовательское пространство.

---

## 3. Сетевой или межсетевой уровень

Сетевой уровень (`network layer` или `internet layer`) определяет, как перемещать пакеты от исходного хоста к конечному.

Основной набор правил межсетевой передачи называется:

```
Internet Protocol
IP
```

В книге рассматриваются:

- IPv4;
- IPv6.

Важная особенность сетевых уровней заключается в их аппаратной независимости.

На одном хосте можно одновременно иметь несколько независимых сетевых уровней.

---

## 4. Физический уровень

Физический уровень определяет, как отправлять необработанные данные через физический носитель.

Примеры:

- Ethernet;
- модем.

Этот уровень также иногда называют:

- уровнем сетевого доступа;
- уровнем хост-сети.

---

## Как данные проходят через стек

Если хост A отправляет данные хосту Б:

```
Хост A

Приложение
    ↓
Транспортный уровень
    ↓
Сетевой уровень
    ↓
Физический уровень
    ↓
──────────────────────
     физическая сеть
──────────────────────
    ↓
Физический уровень
    ↓
Сетевой уровень
    ↓
Транспортный уровень
    ↓
Приложение

Хост Б
```

Данные проходят через сетевые уровни как минимум дважды:

1. вниз по стеку на отправляющем хосте;
2. вверх по стеку на принимающем хосте.

Если данные проходят через маршрутизатор, они также проходят через соответствующие уровни маршрутизатора.

При этом маршрутизатор обычно не обязан обрабатывать абсолютно все уровни так же, как конечный хост.

---

## Важное замечание

Границы между уровнями не всегда абсолютно строгие.

Некоторые устройства могут одновременно просматривать информацию нескольких уровней, например:

- физического;
- сетевого;
- транспортного.

Это может использоваться для более быстрого:

- фильтрования;
- маршрутизации данных.

Книга также отмечает, что название TLS (`Transport Layer Security`) может сбивать с толку: несмотря на название, TLS относится к прикладному уровню в используемой здесь модели.
