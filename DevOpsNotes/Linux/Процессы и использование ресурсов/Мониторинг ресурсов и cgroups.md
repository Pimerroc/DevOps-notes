## Основные ресурсы

Глава рассматривает три основных аппаратных ресурса:

```text
CPU
память
ввод-вывод
````

Процессы конкурируют за них.

Поэтому мониторинг должен отвечать не просто на вопрос:

```
Система медленная?
```

а на более конкретные вопросы:

```
CPU перегружен?
Не хватает памяти?
Система ждёт I/O?
Какой процесс использует ресурс?
```

---

# CPU time

Использование CPU измеряется через процессорное время.

Это время, которое процесс фактически получает от процессора.

Оно не обязательно совпадает с обычным временем выполнения программы.

---

# Приоритет процессов

Ядро распределяет процессорное время между процессами.

Процессу можно задавать приоритет.

Изменение приоритета влияет на то, как процесс конкурирует с другими процессами за процессорное время.

---

# Load average

Среднее значение загрузки показывает количество работы, ожидающей обработки системой.

Это полезный показатель общей нагрузки, но сам по себе он не объясняет причину.

Высокая загрузка может быть связана с:

- процессором;
- ожиданием ресурсов;
- другими процессами.

Поэтому load average необходимо рассматривать вместе с другой статистикой.

---

# Память

При мониторинге памяти необходимо различать различные виды её использования.

Linux активно использует память для ускорения работы системы, поэтому большое использование памяти само по себе не обязательно является проблемой.

Проблемы начинаются при недостатке памяти для активно работающих процессов.

Тогда система может обращаться к области подкачки.

Частое использование подкачки может серьёзно ухудшить производительность из-за медленного дискового ввода-вывода.

---

# vmstat

Команда:

```
vmstat
```

используется для наблюдения за состоянием:

- процессора;
- памяти;
- виртуальной памяти;
- ввода-вывода.

Она позволяет наблюдать изменения показателей во времени.

---

# I/O

Мониторинг ввода-вывода важен, поскольку процесс может не использовать активно CPU, а ожидать:

```
диск
другое устройство
операцию ввода-вывода
```

Поэтому низкое использование CPU не всегда означает отсутствие нагрузки.

---

# pidstat

Команда:

```
pidstat
```

используется для наблюдения за использованием ресурсов отдельными процессами.

Это позволяет перейти от:

```
проблемы всей системы
```

к:

```
конкретному процессу
```

---

# cgroups

Группы управления:

```
cgroups
```

позволяют ядру группировать процессы для управления ресурсами.

Идея:

```
процессы
   ↓
группа
   ↓
контроль ресурсов
```

Это позволяет работать не только с отдельными процессами, но и с группами процессов как с единым объектом управления.

Глава рассматривает:

- различия между версиями cgroup;
- просмотр существующих cgroups;
- создание и управление ими.

---

## Общая модель мониторинга

```
система работает медленно
        │
        ▼
какой ресурс ограничен?
        │
   ┌────┼────┐
   ▼    ▼    ▼
 CPU  memory  I/O
   │    │     │
   ▼    ▼     ▼
process/process group
        │
        ▼
конкретная причина
```

Главная цель инструментов мониторинга — понять, **какой ресурс используется и кем**, а не просто изменять настройки системы в попытке увеличить производительность.
- В **cgroups v1** каждый тип контроллера (cpu, memory и т. д.) имеет собственный набор cgroups. Процесс может принадлежать одной группе на контроллер, то есть он может принадлежать нескольким группам. Например, в v1 процесс может принадлежать группам cpu и memory.
- В **cgroups v2** процесс может принадлежать только одной группе cgroup. Вы можете настроить различные типы контроллеров для каждой группы.

Все группы находятся в директории `/sys/fs/cgroup`
можно посмотреть активные группы: `cat /proc/self/cgroup`
Для создания группы просто создайте директорию
```bash
mkdir my_group
```
и вместе с ней создадутся все необходимые для конфигурации файлы, 
такие как `pids.current` (сюда добавляются отслеживаемые процессы),
`memory.max`, `pids.max` etc.
Для удаление используется `rmdir`, но работает он только если в `pids.current` нет процессов (тоесть даже если в директории есть конфиг файлы она все равно удалиться).
