Docker предоставляет удобный способ создавать контейнеры из заранее подготовленных **образов (images)**.

Важно не путать образ и контейнер:

- **образ** содержит файловую систему и определения, необходимые для создания контейнера;
- **контейнер** — это уже запущенное окружение, внутри которого выполняются процессы.

Полезная модель из книги: образ можно приблизительно представить как файловую систему контейнера, однако изменения файлов внутри контейнера сами по себе не изменяют исходный образ.

### Dockerfile

Образ можно создать с помощью файла `Dockerfile`. Например, книга использует:

```
FROM alpine:latest
RUN apk add bash
CMD ["/bin/bash"]
```

Здесь:

- `FROM` определяет базовый образ;
- `RUN` выполняет действие **при сборке образа**;
- `CMD` задаёт действие, связанное с запуском контейнера.

В примере используется минимальный образ Alpine, в который добавляется `bash`.

Сборка выполняется:

```
docker build -t hlw_test .
```

Docker последовательно обрабатывает инструкции `Dockerfile`. При выполнении `RUN` создаётся временный контейнер, внутри него выполняется команда, после чего полученные изменения сохраняются в промежуточный образ. Затем временный контейнер удаляется. В конце формируется итоговый образ.

Ключевой момент:

```
RUN  → выполняется при сборке образа
CMD  → относится к запуску контейнера
```

После сборки образ можно увидеть:

```
docker images
```

Образы имеют репозиторий, тег и идентификатор. Например, один и тот же образ можно обозначить `hlw_test`, `hlw_test:latest` или его идентификатором.

### Запуск контейнера

Книга запускает контейнер командой:

```
docker run -it hlw_test
```

Параметры `-i` и `-t` предназначены для интерактивной работы с терминалом. В результате внутри контейнера появляется оболочка `bash`.

Внутри контейнера процессы являются теми же Linux-процессами, но благодаря механизмам изоляции контейнер видит только собственное окружение. В приведённом примере `bash` имеет внутри контейнера PID 1.

Docker также позволяет удалять старые образы с помощью `docker rmi`. При постоянной пересборке старые образы без тегов могут накапливаться и занимать значительный объём дискового пространства.

### Docker и Podman

В книге кратко сравниваются Docker и Podman.

Основное различие состоит в архитектуре запуска:

- Docker использует работающий сервер/демон;
- Podman может работать без отдельного сервера;
- Podman поддерживает **rootless-режим**, то есть контейнер можно запускать от обычного пользователя;
- команды Podman в значительной степени совместимы с командами Docker.

Более новые версии Docker также поддерживают rootless-режим.
