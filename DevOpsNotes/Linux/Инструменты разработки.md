## 1. Компилятор C и объектные файлы

Исходный код C необходимо преобразовать в двоичную форму, понятную процессору.

Для нескольких исходных файлов процесс выглядит примерно так:

```
main.c ──► main.o ─┐
                   ├──► linker ──► executable
aux.c  ──► aux.o ──┘
```

Пример из книги:

```
cc -o myprog main.o aux.o
```

Проблема ручного управления большим количеством исходных файлов заключается в необходимости отслеживать зависимости между ними. Для этого используется `make`.

## 2. Статические и разделяемые библиотеки

Статическая библиотека имеет расширение:

```
.a
```

Например:

```
libcurses.a
```

При статической линковке необходимый машинный код копируется непосредственно в исполняемый файл.

```
library.a
   │
   ▼
linker
   │
   ▼
executable
```

После этого исполняемому файлу библиотека во время запуска уже не требуется.

Разделяемые библиотеки устроены иначе: код библиотеки не копируется целиком в каждый исполняемый файл, а загружается динамическим компоновщиком.

Для поиска библиотек используется, среди прочего:

```
/etc/ld.so.conf
/etc/ld.so.cache
```

Книга отдельно предупреждает против использования:

```
LD_LIBRARY_PATH
```

в файлах запуска.

## 3. `make`

`make` автоматизирует сборку программы на основании зависимостей.

Основой является:

```
Makefile
```

В нём описываются:

```
цель
зависимости
команды
```

Например, если:

```
myprog зависит от main.o и aux.o
```

`make` может пересобрать только необходимые части.

Книга подчёркивает важность **табуляции** перед командами в `Makefile`: `make` строго относится к этому синтаксису.

## 4. Препроцессор и другие инструменты

Препроцессор C позволяет:

```
#define
#ifdef
#if
#endif
```

изменять исходный текст до его передачи компилятору.

Макросы можно задавать и из командной строки:

```
cc -DBLAH=something ...
```

Глава также рассматривает:

```
Lex
Yacc
Python
Perl
Java
```

как инструменты, которые могут использоваться в разработке программного обеспечения.
