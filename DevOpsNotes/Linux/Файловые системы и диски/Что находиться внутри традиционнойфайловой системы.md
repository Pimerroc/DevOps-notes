Традиционная файловая система Unix состоит из двух основных компонентов:

* **пула блоков данных**, где хранится информация;
* **системы структур данных**, управляющей этим пулом.

Основой второй части является **inode (дескриптор)** — структура, описывающая конкретный файл: его тип, права доступа и расположение данных в пуле блоков. Inode идентифицируются номерами в таблице inode.

Каталоги также представлены inode. Их данные содержат список имён и ссылок на соответствующие inode. Благодаря связи **«имя → inode → данные»** создаётся иерархия файловой системы.
На изображениях показан пример в созданой пустой файловой системы с такой последовательностью команд:
```bash
$ mkdir dir_1
$ mkdir dir_2
$ echo a > dir_1/file_1
$ echo b > dir_1/file_2
$ echo c > dir_1/file_3
$ echo d > dir_2/file_4
$ ln dir_1/file_3 dir_2/file_5
```

В `ext2/ext3/ext4` корневым inode является **inode 2**. Для поиска файла ядро последовательно разбирает компоненты пути, начиная с корневого inode, находит соответствующие записи каталогов и в конечном итоге получает inode нужного файла. После этого оно использует информацию inode для доступа к данным файла.

Каталоги содержат специальные записи `.` (текущий каталог) и `..` (родительский каталог), что позволяет перемещаться по иерархии.

## Количество ссылок

**Link count** — количество записей каталогов, указывающих на определённый inode.

Обычный файл обычно имеет одну ссылку. **Жёсткая ссылка** создаёт дополнительную запись каталога, указывающую на уже существующий inode, поэтому несколько имён могут представлять один файл.

При удалении имени уменьшается количество ссылок. Если оно становится равным нулю, inode и связанные с ним данные могут быть удалены. Если остаются другие ссылки, данные сохраняются.

Для каталогов количество ссылок связано также с записями `.` и `..`. У корневого inode есть дополнительная ссылка из суперблока, указывающая на корневой inode.

## Распределение блоков

Для отслеживания свободных и занятых блоков может использоваться **block bitmap** — битовая карта блоков. Каждый бит соответствует блоку:

* `0` — блок свободен;
* `1` — блок используется.

Проблемы возникают, если информация inode, структуры каталогов, количество ссылок и распределение блоков перестают соответствовать друг другу. `fsck` проверяет эти структуры, восстанавливает количество ссылок и карту распределения блоков, а также обрабатывает данные, не связанные со структурой каталогов. Такие «осиротевшие» файлы обычно помещаются в `lost+found`.

## Файловая система в пользовательском пространстве

Пользовательские программы работают с файлами через системные вызовы ядра. Например, `stat()` возвращает номер inode и количество ссылок.

Эти внутренние понятия не обязательно имеют то же значение во всех файловых системах. **VFS** предоставляет единый интерфейс для разных файловых систем, скрывая их внутреннюю реализацию.

Поэтому некоторые Unix-операции могут быть недоступны в нетрадиционных файловых системах. Например, **VFAT** не поддерживает создание жёстких ссылок.

Файловые системы также могут реализовываться в **пользовательском пространстве**: в этом случае ядро в основном обеспечивает передачу системных вызовов соответствующему процессу.
