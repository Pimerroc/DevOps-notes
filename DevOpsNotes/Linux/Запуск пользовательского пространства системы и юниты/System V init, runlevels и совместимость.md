## Уровни выполнения

В System V init используется понятие:

```text
runlevel
````

Уровень выполнения определяет состояние работы системы.

Традиционно разные уровни использовались для:

- обычной работы;
- однопользовательского режима;
- текстовой консоли;
- графического режима;
- выключения системы.

Проверить уровень выполнения можно командой:

```
who -r
```

Пример:

```
run-level 5
```

Традиционно уровни:

```
2–4
```

использовались для текстовой консоли, а:

```
5
```

обычно означал запуск графического входа.

В systemd концепция уровней выполнения считается устаревшей.

Вместо неё используются:

```
target units
```

Уровни выполнения в systemd в основном сохраняются для совместимости со старыми сценариями System V.

## Как работает System V init

System V init основана на:

```
/etc/inittab
```

и наборе сценариев запуска.

Типичная конфигурация состоит из:

```
/etc/inittab
        +
сценарии запуска
        +
ферма символических ссылок
```

Пример строки:

```
id:5:initdefault:
```

Она определяет уровень выполнения по умолчанию.

Строка `inittab` состоит из четырёх полей:

```
id:runlevels:action:command
```

где:

1. `id` — уникальный идентификатор;
2. `runlevels` — применимые уровни выполнения;
3. `action` — действие init;
4. `command` — команда для выполнения.

## Последовательный запуск

Основная идея System V init:

```
service A
   ↓
service B
   ↓
service C
```

Сценарии запускаются в определённом порядке.

Это делает процесс понятным, но создаёт ограничение:

```
даже независимые задачи
могут ждать друг друга
```

Современные системы пытаются запускать независимые компоненты параллельно.

---

## Совместимость с systemd

System V init сегодня редко используется в типичных настольных и серверных системах.

Однако старые пакеты могут содержать только сценарии System V.

systemd может работать с такими сценариями в режиме совместимости.

Таким образом:

```
старый SysV script
       ↓
совместимость systemd
       ↓
работа службы в современной системе
```

## Главное отличие моделей

### System V

```
сценарии
   ↓
строгий порядок
   ↓
последовательный запуск
```

### systemd

```
юниты
   ↓
зависимости
   ↓
граф
   ↓
активация готовых компонентов
```
