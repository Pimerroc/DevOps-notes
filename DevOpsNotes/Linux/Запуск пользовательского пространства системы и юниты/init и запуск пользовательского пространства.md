## Переход от ядра к пользовательскому пространству

После загрузки ядра Linux начинается запуск пользовательского пространства.

Ключевой момент этого процесса — запуск программы:

```text
init
````

Это первый процесс пользовательского пространства.

После запуска `init` система начинает последовательно создавать остальную рабочую среду.

Общий порядок запуска пользовательского пространства:
```
1. init
2. Основные службы низкого уровня
3. Конфигурация сети
4. Службы среднего и высокого уровня
5. Вход пользователей и высокоуровневые приложения
```

Пример:

```
Linux kernel
      ↓
init
      ↓
udevd, syslogd
      ↓
network configuration
      ↓
cron, printing и другие службы
      ↓
getty / graphical interface
      ↓
пользовательские приложения
```

## Что делает init

`init` — это обычная программа пользовательского пространства.

Её основная задача:

- запускать основные системные службы;
- останавливать основные системные службы;
- управлять процессом запуска системы.

Различные реализации `init` существуют потому, что традиционная схема запуска имела ограничения.

## Традиционный System V init

Традиционный System V init представляет запуск системы как последовательность сценариев:

```
script 1
   ↓
script 2
   ↓
script 3
   ↓
...
```

Обычно каждый сценарий:

- запускает одну службу;
- либо настраивает отдельную часть системы.

Главный недостаток такой модели — последовательность.

Если две операции не зависят друг от друга, они всё равно обычно запускаются одна за другой.

Это снижает производительность загрузки.

Другие проблемы:

- сложно отслеживать работающие демоны;
- приходится искать PID службы через `ps`, PID-файлы или другие механизмы;
- сценарии часто содержат большое количество шаблонного кода;
- большинство служб запускается сразу при загрузке;
- поддержка запуска служб по требованию ограничена.

Современные системы инициализации изменили:

- способ запуска служб;
- способ управления ими;
- механизм зависимостей.

## Определение системы init

Система может использовать различные реализации.

### systemd

Признаки:

```
/usr/lib/systemd
/etc/systemd
```

### Upstart

Признак:

```
/etc/init
```

с несколькими файлами:

```
*.conf
```

### System V init

Если предыдущих каталогов нет, но существует:

```
/etc/inittab
```

то система, вероятно, использует System V init.

## Главная идея

`init` — это начало пользовательского пространства.

После:

```
kernel
```

начинается:

```
init
   ↓
службы
   ↓
сеть
   ↓
пользовательский вход
   ↓
рабочая система
```

В современных основных дистрибутивах Linux стандартной реализацией `init` является:

```
systemd
```
